1. Co instalujesz

Compass Hub to usługa zespołowa Loonar Compass. Jest to jeden program, compass-hub.exe, bez instalatora i bez Enterprise Architect. Działa jako usługa Windows i przechowuje:

  • modele EA zespołu (tylko do odczytu): pliki .qea/.qeax albo repozytorium PostgreSQL, SQL Server, MySQL lub Oracle;
  • politykę zespołu, którą stosują aplikacje Compass: minimalny tryb zatwierdzania, dostęp do internetu, AI tylko przez hub itd.;
  • dziennik audytu zmian ze wszystkich stacji, zestawy zmian do przeglądu i widok webowy dla osób bez EA;
  • bramkę AI: klucze Claude API zostają na serwerze, z kluczem i limitami na osobę lub rolę;
  • Jirę i Confluence przez jedno konto serwisowe, API GraphQL tylko do odczytu, tabele dla Power BI i serwer MCP.

To jest konfiguracja przetestowana od początku do końca na Windows Server 2022 z AD, AD CS, AD FS i IIS. Każdy krok kończy się sprawdzeniem, więc problem wychodzi w kroku, który go spowodował.

3. Krok 1 – Pliki i folder

  1. Sprawdź SHA-256 pobranego pliku z wartością opublikowaną przy wydaniu: 
    Get-FileHash .\CompassHub-0.9.0-windows-x64.zip -Algorithm SHA256
  2. Rozpakuj go do C:\CompassHub i utwórz podfoldery models i secrets.
  3. Ogranicz dostęp do folderu do usługi i administratorów. Hub zapisuje tu swoje dane, a tu leżą sekrety: 
    icacls C:\CompassHub /inheritance:r /grant:r "SYSTEM:(OI)(CI)F" "BUILTIN\Administrators:(OI)(CI)F"
    W polskim Windows grupa nazywa się BUILTIN\Administratorzy; zamiast nazwy można podać SID *S-1-5-32-544.

Sprawdzenie: C:\CompassHub\compass-hub.exe --version wypisuje 0.9.0.

4. Krok 2 – hub.json i modele

Skopiuj hub.example.json do C:\CompassHub\hub.json. Minimalny start:

{
  "listen": "127.0.0.1:8730",
  "sources": [
    { "id": "architecture", "name": "Architektura korporacyjna", "properties": "models/architecture.properties" }
  ],
  "policy": { "min_approval": "ask" }
}
  • listen zostaje na 127.0.0.1: z hubem rozmawia tylko IIS na tym samym serwerze.
  • sources: jeden wpis na model. id ma być krótkie i stałe, bo używają go użytkownicy i Power BI. properties jest względne wobec hub.json.
  • Pomiń users: hub utworzy wtedy konto admin (krok 4) i sam zapisze użytkowników, tylko jako skróty.

Plik modelu, np. C:\CompassHub\models\architecture.properties:

# Plik projektu EA (tylko odczyt)
model.source=file
model.file=C:/CompassHub/models/Architecture.qea

# ... albo baza repozytorium (hasło to sekret DB_PASSWORD):
# model.source=sqlserver          (albo postgres, mysql, oracle)
# db.host=sql.firma.pl
# db.port=1433
# db.name=ea_repository
# db.user=compass_reader
# db.sslmode=verify-full

SQL Server, MySQL i Oracle są czytane przez 64-bitowy sterownik ODBC producenta, który musi być zainstalowany na serwerze. Dla SQL Server wystarczy „ODBC Driver 17 for SQL Server” (instaluje się z SQL Server 2022) albo 18; zainstalowane sterowniki: Get-OdbcDriver -Name '*SQL Server*' -Platform 64-bit. PostgreSQL i pliki nie potrzebują niczego więcej. Każdy odczyt jest wycofywany, więc wystarczy konto bazy tylko do odczytu. SQL Server bez sekretu DB_PASSWORD używa uwierzytelniania Windows: usługa huba (LocalSystem) loguje się kontem komputera (DOMENA\SERWER$), które potrzebuje roli db_datareader w bazie modelu.

  • Instancja nazwana (np. SQL Server Express): db.host=SERWER\SQLEXPRESS bez portu, przy działającej usłudze SQL Server Browser; albo stały port TCP (SQL Server Configuration Manager → TCP/IP → IPAll: TcpPort 1433, TcpDynamicPorts puste) i db.host/db.port.
  • Własny ciąg połączenia: db.odbc=Driver={ODBC Driver 17 for SQL Server};Server=sql.firma.pl,1433;Database=ea_repository;Trusted_Connection=Yes zastępuje host, port, nazwę i użytkownika (bez hasła; DB_PASSWORD, jeśli jest, zostaje dodane).
  • db.sslmode dla SQL Server: prefer = szyfrowanie, gdy serwer i sterownik go używają (bez sprawdzania certyfikatu); require = zawsze szyfrowane, certyfikat nie jest sprawdzany; verify-full = szyfrowane, a certyfikat musi być zaufany i zgodny z nazwą serwera (nie z certyfikatem samopodpisanym SQL Server).
Trzymaj pliki modeli huba osobno od plików, które ludzie edytują w EA. Aby odświeżyć model plikowy, podmień plik. Hub otwiera go tylko do odczytu przy każdym zapytaniu, więc restart nie jest potrzebny.

5. Krok 3 – Sekrety

Każdy sekret to plik tekstowy w C:\CompassHub\secrets, który zawiera tylko wartość. Usługa poznaje ścieżkę ze zmiennej środowiskowej LOONAR_SECRET_<NAZWA>_FILE. Plik tworzy osoba, która zna wartość, np. w Notatniku albo poleceniem:

Read-Host -AsSecureString "Wartość" | ConvertFrom-SecureString -AsPlainText | Set-Content C:\CompassHub\secrets\claude_key_team -NoNewline

(-AsPlainText wymaga PowerShell 7; w Windows PowerShell 5.1 prościej użyć Notatnika.)

Plik (przykład)Zmienna dla usługiPotrzebny do
claude_key_teamLOONAR_SECRET_CLAUDE_KEY_TEAM_FILEBramka AI: jedna zmienna na każdy klucz wskazany w hub.json (krok 7)
claude_api_keyLOONAR_SECRET_CLAUDE_API_KEY_FILE„Zapytaj” w widoku webowym
jira_tokenLOONAR_SECRET_JIRA_TOKEN_FILEJira
confluence_tokenLOONAR_SECRET_CONFLUENCE_TOKEN_FILEConfluence
oidc_client_secretLOONAR_SECRET_OIDC_CLIENT_SECRET_FILELogowanie kontem firmowym
db_passwordLOONAR_SECRET_DB_PASSWORD_FILEBaza modelu

Nazwa w zmiennej to nazwa sekretu wielkimi literami, z innymi znakami zamienionymi na _: sekret claude_key_anna z hub.json to LOONAR_SECRET_CLAUDE_KEY_ANNA_FILE.

Zmienne ustawia się tylko dla usługi, nie dla całego komputera, po zainstalowaniu usługi (krok 4). Działa to od następnego startu usługi, bez restartu serwera:

$vars = @(
  'LOONAR_SECRET_CLAUDE_KEY_TEAM_FILE=C:\CompassHub\secrets\claude_key_team',
  'LOONAR_SECRET_JIRA_TOKEN_FILE=C:\CompassHub\secrets\jira_token',
  'LOONAR_SECRET_CONFLUENCE_TOKEN_FILE=C:\CompassHub\secrets\confluence_token',
  'LOONAR_SECRET_OIDC_CLIENT_SECRET_FILE=C:\CompassHub\secrets\oidc_client_secret'
  # 'HTTPS_PROXY=http://proxy.firma.pl:8080'   tylko gdy serwer wychodzi przez proxy
)
Set-ItemProperty HKLM:\SYSTEM\CurrentControlSet\Services\CompassHub -Name Environment -Type MultiString -Value $vars
Restart-Service CompassHub

Hub czyta sekret, gdy pierwszy raz go potrzebuje. Brakujący jest zgłaszany tam, gdzie jest używany, np. „secret 'jira_token' is not set: give it as LOONAR_SECRET_JIRA_TOKEN (or a file named in LOONAR_SECRET_JIRA_TOKEN_FILE)”. Wartości nigdy nie pojawiają się w hub.json, w logach ani w widoku webowym. Znacznik BOM na początku oraz spacje i znak nowej linii na końcu pliku sekretu (Notatnik) są pomijane.

6. Krok 4 – Usługa Windows i pierwsze logowanie

  1. W PowerShell jako administrator: 
    C:\CompassHub\compass-hub.exe --service-install C:\CompassHub\hub.json
    Polecenie tworzy usługę CompassHub („Compass Hub (Loonar Compass team service)”) z automatycznym startem na koncie LocalSystem i ją uruchamia.
  2. Teraz ustaw sekrety usługi (krok 3) i wykonaj Restart-Service CompassHub.
  3. Na serwerze otwórz http://127.0.0.1:8730/ i zaloguj się jako admin / passw0rd (z zerem). Hub od razu żąda nowego hasła i do tego czasu nie pozwala na nic innego. Hasło ma co najmniej 10 znaków. Zrób to przed krokiem 5, który udostępni hub w sieci.

Sprawdzenie:

  • Get-Service CompassHub pokazuje Running;
  • C:\CompassHub\hub.log pokazuje start i Twoje logowanie;
  • widok webowy pokazuje model z kroku 2.

7. Krok 5 – HTTPS przez IIS (URL Rewrite + ARR)

Hub mówi zwykłym HTTP na 127.0.0.1. IIS daje mu firmową nazwę i certyfikat.

  1. Zainstaluj IIS z URL Rewrite i ARR. Utwórz witrynę, np. CompassHub, z powiązaniem https, port 443, nazwą hosta hub.firma.pl i certyfikatem. Ścieżka fizyczna to pusty folder, np. C:\inetpub\compasshub.
  2. Włącz proxy i wyłącz przepisywanie hosta w przekierowaniach. To jest konieczne; inaczej ARR przepisze przekierowanie do AD FS na adres huba i logowanie firmowe się nie uda. Ustaw też limit czasu dla długich odpowiedzi AI: 
    Import-Module WebAdministration
$p = 'MACHINE/WEBROOT/APPHOST'
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name enabled -Value True
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name reverseRewriteHostInResponseHeaders -Value False
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name timeout -Value '00:05:00'
  3. Wstaw ten web.config do folderu witryny. Przekazuje on wszystko do huba i pozwala na zapytania do 32 MB, bo pytania z diagramami modelu są duże: 
    <?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="CompassHub" stopProcessing="true">
          <match url="(.*)" />
          <action type="Rewrite" url="http://127.0.0.1:8730/{R:1}" />
        </rule>
      </rules>
    </rewrite>
    <security>
      <requestFiltering>
        <requestLimits maxAllowedContentLength="33554432" />
      </requestFiltering>
    </security>
  </system.webServer>
</configuration>
  4. Zapora: wpuść tylko ruch przychodzący 443. Portu 8730 nie otwiera się nigdy, bo hub nasłuchuje na 127.0.0.1.
  5. AD FS na tym samym serwerze: AD FS też używa portu 443 (HTTP.sys). Zaznacz Wymagaj oznaczania nazwy serwera (SNI) w powiązaniu IIS (New-WebBinding … -SslFlags 1), inaczej IIS i AD FS sobie przeszkadzają.
  6. Hub nie potrzebuje preserveHostHeader ani X-Forwarded-Proto: jego adresy wynikają z redirect_uri w hub.json.

Hub ufa nagłówkowi X-Forwarded-For (dodawanemu przez ARR) tylko od proxy na tym samym komputerze. Dziennik audytu i blokada błędnych tokenów widzą wtedy prawdziwy adres klienta.

Sprawdzenie: ze stacji roboczej https://hub.firma.pl/ pokazuje stronę logowania bez ostrzeżenia o certyfikacie.

8. Krok 6 – Logowanie kontem firmowym (AD FS lub Entra ID)

AD FS

  1. AD FS Management → Application Groups → Add, potem szablon Server application accessing a web API, nazwa „Compass Hub”.
  2. Server application:
    • zanotuj client identifier;
    • redirect URI: https://hub.firma.pl/auth/callback;
    • credentials: Generate a shared secret. Zapisz go od razu do C:\CompassHub\secrets\oidc_client_secret; AD FS pokazuje go tylko raz.
  3. Web API:
    • identifier: client identifier z poprzedniego kroku;
    • access control policy: osoby, które mogą używać huba, np. „Permit everyone” (role i tak wynikają z grup);
    • permitted scopes: openid, profile, email, allatclaims.
  4. Web API → Issuance Transform Rules → „Send LDAP Attributes as Claims” (Active Directory):
    • User-Principal-Name → upn;
    • E-Mail-Addresses → email;
    • Display-Name → name;
    • Token-Groups - Unqualified Names → groups.
    (Nazwy oświadczeń wyjściowych wpisz dokładnie tak.)

W hub.json (hub sam dodaje allatclaims dla AD FS, żeby oświadczenia trafiły do ID tokenu):

"oidc": {
  "issuer": "https://adfs.firma.pl/adfs",
  "client_id": "<client identifier>",
  "redirect_uri": "https://hub.firma.pl/auth/callback",
  "groups_claim": "groups",
  "roles": { "admin": ["Compass-Admins"], "architect": ["Compass-Architects"], "viewer": ["Compass-Viewers"] },
  "password_login": true
}

Microsoft Entra ID

Konfiguracja w Entra ID:

  • App registration: platforma Web, redirect URI https://hub.firma.pl/auth/callback, client secret (do pliku sekretu) i ID token z opcjonalnymi oświadczeniami upn i email.
  • Issuer: https://login.microsoftonline.com/<tenant-id>/v2.0.
  • Grupy: Entra domyślnie wysyła ich identyfikatory obiektów. Wpisz te identyfikatory w roles albo, dla grup synchronizowanych z AD, wybierz „sAMAccountName” w konfiguracji tokenu.

Zasady, które stosuje hub

  • Rola wynika z grup przy każdym logowaniu i wygrywa najwyższa. Osoba spoza wszystkich grup nie dostaje dostępu.
  • Konto firmowe o tej samej nazwie co lokalny użytkownik huba jest odrzucane, dopóki lokalny użytkownik nie zostanie przemianowany lub usunięty.
  • Hub sam sprawdza ID token: podpis RS256, wystawcę, odbiorcę, ważność i nonce, z PKCE i jednorazowym state.
  • Gdy wszystko działa, ustaw "password_login": false: zostaje tylko przycisk konta firmowego. Tokeny API dla klientów MCP dalej działają. Zachowaj w sejfie haseł jedno lokalne hasło admina na wypadek awarii dostawcy tożsamości.

Sprawdzenie: po Restart-Service CompassHub przycisk „Sign in with your company account” prowadzi do AD FS i z powrotem. hub.log pokazuje „… signed in with a company account as architect”, a zakładka Users pokazuje konto firmowe z rolą.

9. Krok 7 – Klucze AI, Jira, Confluence i polityka zespołu

Dodaj sekcje do hub.json. Każdy wskazany tu sekret potrzebuje też swojej zmiennej …_FILE (krok 3). Potem wykonaj Restart-Service CompassHub; zalogowane osoby pozostają zalogowane.

"ai": {
  "keys":   [ { "for": "role:architect", "secret": "claude_key_team" },
              { "for": "anna@firma.pl", "secret": "claude_key_anna" } ],
  "limits": [ { "for": "*", "tokens_per_day": 2000000, "tokens_per_month": 30000000 } ],
  "models": [ "claude-haiku-5-5", "claude-sonnet-5-5" ]
},
"integrations": {
  "jira":       { "url": "https://firma.atlassian.net", "user": "svc-compass@firma.pl", "project": "ARCH", "issue_type": "Task" },
  "confluence": { "url": "https://firma.atlassian.net/wiki", "user": "svc-compass@firma.pl", "space": "ARCH" }
},
"policy": {
  "min_approval": "ask",
  "ai_via_hub": true,
  "jira_via_hub": true,
  "confluence_via_hub": true,
  "web_access": false,
  "update_check": false
}
UstawienieZnaczenie
ai.keysKtórego klucza Claude używa osoba. Kolejność: nazwa użytkownika, potem role:<rola>, potem *. Brak dopasowania oznacza brak AI dla tej osoby.
ai.limitsTokeny na dzień i na miesiąc. Po przekroczeniu hub odmawia z czytelnym komunikatem.
ai.modelsDozwolone modele; inne są odrzucane.
policy.ai_via_hubCompass pyta AI tylko przez hub: na stacjach nie ma klucza API.
policy.jira_via_hub, confluence_via_hubJira/Confluence przez konto serwisowe huba. Viewer może tylko czytać; każda zmiana jest w audycie.
policy.min_approvalNajsłabszy dozwolony w Compass tryb zatwierdzania zapisów do modelu (ask jest najostrzejszy).
policy.web_access, web_allowed_domainsCzy asystent może szukać w internecie i czytać strony, i z jakich domen.
policy.update_checkCzy Compass co godzinę sprawdza na GitHubie nową wersję.

Administratorzy zmieniają później politykę w zakładce Team policy widoku webowego, a zużycie na osobę jest w Users → AI usage.

10. Krok 8 – Stacje robocze (zasady grupy)

  1. Zaufanie do certyfikatu. Jeśli certyfikat huba pochodzi z firmowego CA, rozdaj jego główny urząd na stacje (GPO: Konfiguracja komputera → Zasady → Ustawienia systemu Windows → Ustawienia zabezpieczeń → Zasady kluczy publicznych → Zaufane główne urzędy certyfikacji). Bez tego Compass zgłasza niezaufany certyfikat (UnknownIssuer).
  2. Szablony. Skopiuj LoonarCompass.admx do \\<domena>\SYSVOL\<domena>\Policies\PolicyDefinitions, a pl-PL\LoonarCompass.adml (i en-US) do podfolderów językowych. Bez magazynu centralnego skopiuj je do C:\Windows\PolicyDefinitions na komputerze, na którym edytujesz GPO.
  3. GPO dla OU stacji: Konfiguracja komputera → Szablony administracyjne → Loonar → Loonar Compass.

Bez domeny te same wartości można zaimportować plikiem LoonarCompass-company-policy.reg (i usunąć plikiem LoonarCompass-remove-policy.reg). Zasady komputera są silniejsze niż polityka huba i ustawienia użytkownika; mogą Compass tylko zaostrzyć.

Instalacja Compass. LoonarCompass-Setup-0.9.exe instaluje dla bieżącego użytkownika (%LOCALAPPDATA%\Programs\Loonar Compass) albo dla wszystkich (Program Files) i rejestruje dodatek w Enterprise Architect. Dla narzędzi wdrożeniowych (Intune, Configuration Manager, skrypt startowy) instaluje bez okna:

LoonarCompass-Setup-0.9.exe --quiet --all-users

To samo polecenie aktualizuje istniejącą instalację. Najpierw zamknij Compass i EA na komputerze. Ustawienia użytkownika nie są zmieniane; przy zasadach komputera (adres huba, wymagany hub) nikt nie musi niczego konfigurować. Pierwsze logowanie użytkownika. W Compass: Ustawienia → Zespół (Compass Hub) → Zaloguj się kontem firmowym. Przeglądarka otwiera AD FS i wraca do Compass. Logowanie trwa 12 godzin i przetrwa restart huba.

Compass: certyfikat niezaufany / UnknownIssuer; przeglądarka pokazuje „Niezabezpieczona”Stacja nie ufa głównemu urzędowi certyfikatu huba. Rozdaj główny urząd CA (krok 8), potem uruchom ponownie przeglądarkę i Compass.

14. Linux i Docker

Ten sam hub działa w kontenerze. Folder danych (hub.json z "listen": "0.0.0.0:8730", modele i pliki huba) jest montowany jako /data i musi być zapisywalny dla użytkownika 10001. Sekrety pochodzą ze zmiennych LOONAR_SECRET_* albo z sekretów Dockera przez LOONAR_SECRET_*_FILE:

docker run -d --name compass-hub -p 127.0.0.1:8730:8730 -v /srv/compass-hub:/data \
  -e LOONAR_SECRET_CLAUDE_KEY_TEAM_FILE=/run/secrets/claude_key_team \
  ghcr.io/loonar-eu/compass-hub:0.9.0

Przed nim postaw nginx albo inne proxy HTTPS, jak w kroku 5. Proxy ma nie zmieniać nagłówka Location przekierowań, przekazywać X-Forwarded-For, przyjmować zapytania do 32 MB i mieć limit czasu 5 minut. Dla modeli w SQL Server, MySQL lub Oracle zbuduj własny obraz na bazie tego i dodaj linuksowy sterownik ODBC producenta.
