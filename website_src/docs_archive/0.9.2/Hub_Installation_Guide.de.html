1. Was Sie installieren

Compass Hub ist der Teamdienst von Loonar Compass. Er besteht aus einem einzigen Programm, compass-hub.exe, ohne Installationsprogramm und ohne Enterprise Architect. Er läuft als Windows-Dienst und verwaltet:

  • die EA-Modelle des Teams (nur lesend): .qea/.qeax-Dateien oder ein PostgreSQL-, SQL-Server-, MySQL- oder Oracle-Repository;
  • die Teamrichtlinie, der die Compass-Anwendungen folgen: den minimalen Freigabemodus, den Webzugriff, KI nur über den Hub usw.;
  • das Audit-Protokoll der Änderungen von allen Arbeitsplätzen, die Änderungssätze zur Prüfung und eine Weboberfläche für Personen ohne EA;
  • das KI-Gateway: Die Claude-API-Schlüssel bleiben auf dem Server, mit einem Schlüssel und Limits pro Person oder Rolle;
  • Jira und Confluence über ein einziges Dienstkonto, eine schreibgeschützte GraphQL-API, Tabellen für Power BI und einen MCP-Server.

Dies ist die Konfiguration, die durchgängig unter Windows Server 2022 mit AD, AD CS, AD FS und IIS getestet wurde. Jeder Schritt endet mit einer Prüfung, sodass ein Problem in dem Schritt sichtbar wird, der es verursacht hat.

3. Schritt 1 – Dateien und Ordner

  1. Vergleichen Sie den SHA-256-Wert des Downloads mit dem Wert, der mit dem Release veröffentlicht wurde: 
    Get-FileHash .\CompassHub-0.9.0-windows-x64.zip -Algorithm SHA256
  2. Entpacken Sie die Datei nach C:\CompassHub und legen Sie die Unterordner models und secrets an.
  3. Beschränken Sie den Ordner auf den Dienst und die Administratoren. Der Hub schreibt seine Daten hierher, und hier liegen die Geheimnisse: 
    icacls C:\CompassHub /inheritance:r /grant:r "SYSTEM:(OI)(CI)F" "BUILTIN\Administrators:(OI)(CI)F"
    Unter einem Windows in einer anderen Sprache verwenden Sie die SID *S-1-5-32-544 statt des Namens der Gruppe Administratoren.

Prüfung: C:\CompassHub\compass-hub.exe --version gibt 0.9.0 aus.

4. Schritt 2 – hub.json und die Modelle

Kopieren Sie hub.example.json nach C:\CompassHub\hub.json. Ein minimaler Start:

{
  "listen": "127.0.0.1:8730",
  "sources": [
    { "id": "architecture", "name": "Enterprise architecture", "properties": "models/architecture.properties" }
  ],
  "policy": { "min_approval": "ask" }
}
  • listen bleibt auf 127.0.0.1: Nur IIS auf demselben Server spricht mit dem Hub.
  • sources: ein Eintrag pro Modell. id ist kurz und stabil, weil die Benutzer und Power BI sie verwenden. properties ist relativ zu hub.json.
  • Lassen Sie users weg: Der Hub legt dann das Konto admin an (Schritt 4) und schreibt die Benutzer selbst zurück, nur als Hashes.

Die Modelldatei, z. B. C:\CompassHub\models\architecture.properties:

# An EA project file (read only)
model.source=file
model.file=C:/CompassHub/models/Architecture.qea

# ... or a repository database (the password is the secret DB_PASSWORD):
# model.source=sqlserver          (or postgres, mysql, oracle)
# db.host=sql.company.com
# db.port=1433
# db.name=ea_repository
# db.user=compass_reader
# db.sslmode=verify-full

SQL Server, MySQL und Oracle werden über den 64-Bit-ODBC-Treiber des Herstellers gelesen, der auf dem Server installiert sein muss. Für SQL Server genügt „ODBC Driver 17 for SQL Server“ (wird mit SQL Server 2022 mitgeliefert) oder 18; die installierten Treiber: Get-OdbcDriver -Name '*SQL Server*' -Platform 64-bit. PostgreSQL und Dateien benötigen nichts weiter. Jeder Lesevorgang wird zurückgerollt, daher genügt ein schreibgeschütztes Datenbankkonto. SQL Server ohne das Geheimnis DB_PASSWORD verwendet die Windows-Authentifizierung: Der Hub-Dienst (LocalSystem) meldet sich als Computerkonto an (DOMAIN\SERVER$), das dann die Rolle db_datareader in der Modelldatenbank benötigt.

  • Benannte Instanz (z. B. SQL Server Express): db.host=SERVER\SQLEXPRESS ohne Port, bei laufendem Dienst SQL Server Browser; oder ein fester TCP-Port (SQL Server Configuration Manager → TCP/IP → IPAll: TcpPort 1433, TcpDynamicPorts leer) und db.host/db.port.
  • Eigene Verbindungszeichenfolge: db.odbc=Driver={ODBC Driver 17 for SQL Server};Server=sql.company.com,1433;Database=ea_repository;Trusted_Connection=Yes ersetzt Host, Port, Name und Benutzer (ohne Kennwort; DB_PASSWORD wird, falls gesetzt, ergänzt).
  • db.sslmode für SQL Server: prefer = Verschlüsselung, wenn Server und Treiber sie verwenden (keine Zertifikatsprüfung); require = immer verschlüsselt, das Zertifikat wird nicht geprüft; verify-full = verschlüsselt, und das Zertifikat muss vertrauenswürdig sein und zum Servernamen passen (nicht mit einem selbstsignierten SQL-Server-Zertifikat).
Halten Sie die Modelldateien des Hubs getrennt von den Dateien, die in EA bearbeitet werden. Um ein Dateimodell zu aktualisieren, ersetzen Sie die Datei. Der Hub öffnet sie bei jeder Anfrage schreibgeschützt, daher ist kein Neustart nötig.

5. Schritt 3 – Geheimnisse

Jedes Geheimnis ist eine Textdatei in C:\CompassHub\secrets, die nur den Wert enthält. Den Pfad erfährt der Dienst aus einer Umgebungsvariablen LOONAR_SECRET_<NAME>_FILE. Die Person, die den Wert kennt, legt die Datei an, z. B. im Editor (Notepad) oder mit:

Read-Host -AsSecureString "Value" | ConvertFrom-SecureString -AsPlainText | Set-Content C:\CompassHub\secrets\claude_key_team -NoNewline

(-AsPlainText erfordert PowerShell 7; in Windows PowerShell 5.1 ist der Editor einfacher.)

Datei (Beispiel)Variable für den DienstBenötigt für
claude_key_teamLOONAR_SECRET_CLAUDE_KEY_TEAM_FILEDas KI-Gateway: eine Variable pro Schlüssel, der in hub.json genannt ist (Schritt 7)
claude_api_keyLOONAR_SECRET_CLAUDE_API_KEY_FILE„Ask“ in der Weboberfläche
jira_tokenLOONAR_SECRET_JIRA_TOKEN_FILEJira
confluence_tokenLOONAR_SECRET_CONFLUENCE_TOKEN_FILEConfluence
oidc_client_secretLOONAR_SECRET_OIDC_CLIENT_SECRET_FILEFirmenanmeldung
db_passwordLOONAR_SECRET_DB_PASSWORD_FILEEine Modelldatenbank

Der Name in der Variablen ist der Name des Geheimnisses in Großbuchstaben, andere Zeichen werden zu _: Das Geheimnis claude_key_anna aus hub.json wird zu LOONAR_SECRET_CLAUDE_KEY_ANNA_FILE.

Die Variablen werden nur für den Dienst gesetzt, nicht für den ganzen Computer, und zwar nach der Installation des Dienstes (Schritt 4). Sie wirken beim nächsten Start des Dienstes, ohne Neustart des Rechners:

$vars = @(
  'LOONAR_SECRET_CLAUDE_KEY_TEAM_FILE=C:\CompassHub\secrets\claude_key_team',
  'LOONAR_SECRET_JIRA_TOKEN_FILE=C:\CompassHub\secrets\jira_token',
  'LOONAR_SECRET_CONFLUENCE_TOKEN_FILE=C:\CompassHub\secrets\confluence_token',
  'LOONAR_SECRET_OIDC_CLIENT_SECRET_FILE=C:\CompassHub\secrets\oidc_client_secret'
  # 'HTTPS_PROXY=http://proxy.company.com:8080'   only if the server goes out through a proxy
)
Set-ItemProperty HKLM:\SYSTEM\CurrentControlSet\Services\CompassHub -Name Environment -Type MultiString -Value $vars
Restart-Service CompassHub

Der Hub liest ein Geheimnis, wenn er es zum ersten Mal benötigt. Ein fehlendes Geheimnis wird dort gemeldet, wo es verwendet wird, z. B. „secret 'jira_token' is not set: give it as LOONAR_SECRET_JIRA_TOKEN (or a file named in LOONAR_SECRET_JIRA_TOKEN_FILE)“. Die Werte erscheinen nie in hub.json, in den Protokollen oder in der Weboberfläche. Eine Bytereihenfolgemarkierung (BOM) am Anfang sowie Leerzeichen oder ein Zeilenumbruch am Ende einer Geheimnisdatei (Editor) werden ignoriert.

6. Schritt 4 – Der Windows-Dienst und die erste Anmeldung

  1. In PowerShell als Administrator: 
    C:\CompassHub\compass-hub.exe --service-install C:\CompassHub\hub.json
    Dies legt den Dienst CompassHub („Compass Hub (Loonar Compass team service)“) mit automatischem Start unter LocalSystem an und startet ihn.
  2. Setzen Sie nun die Geheimnisse des Dienstes (Schritt 3) und führen Sie Restart-Service CompassHub aus.
  3. Öffnen Sie auf dem Server http://127.0.0.1:8730/ und melden Sie sich als admin / passw0rd (mit einer Null) an. Der Hub verlangt sofort ein neues Kennwort und erlaubt bis dahin nichts anderes. Das Kennwort muss mindestens 10 Zeichen lang sein. Erledigen Sie dies, bevor Schritt 5 den Hub erreichbar macht.

Prüfung:

  • Get-Service CompassHub zeigt Running;
  • C:\CompassHub\hub.log zeigt den Start und Ihre Anmeldung;
  • die Weboberfläche listet das Modell aus Schritt 2 auf.

7. Schritt 5 – HTTPS mit IIS (URL Rewrite + ARR)

Der Hub spricht reines HTTP auf 127.0.0.1. IIS gibt ihm den Firmennamen und das Zertifikat.

  1. Installieren Sie IIS mit URL Rewrite und ARR. Legen Sie eine Site an, z. B. CompassHub, mit einer Bindung für https, Port 443, dem Hostnamen hub.company.com und dem Zertifikat. Der physische Pfad ist ein leerer Ordner, z. B. C:\inetpub\compasshub.
  2. Schalten Sie den Proxy ein und das Umschreiben des Hosts in Weiterleitungen aus. Dies ist erforderlich; andernfalls schreibt ARR die Weiterleitung zu AD FS auf die eigene Adresse des Hubs um, und die Firmenanmeldung schlägt fehl. Setzen Sie außerdem das Timeout für lange KI-Antworten: 
    Import-Module WebAdministration
$p = 'MACHINE/WEBROOT/APPHOST'
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name enabled -Value True
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name reverseRewriteHostInResponseHeaders -Value False
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name timeout -Value '00:05:00'
  3. Legen Sie diese web.config in den Ordner der Site. Sie leitet alles an den Hub weiter und erlaubt Anfragekörper bis 32 MB, weil Fragen mit Modelldiagrammen groß sind: 
    <?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="CompassHub" stopProcessing="true">
          <match url="(.*)" />
          <action type="Rewrite" url="http://127.0.0.1:8730/{R:1}" />
        </rule>
      </rules>
    </rewrite>
    <security>
      <requestFiltering>
        <requestLimits maxAllowedContentLength="33554432" />
      </requestFiltering>
    </security>
  </system.webServer>
</configuration>
  4. Firewall: Erlauben Sie nur eingehend 443. Port 8730 wird nie geöffnet, weil der Hub auf 127.0.0.1 lauscht.
  5. AD FS auf demselben Server: AD FS verwendet ebenfalls Port 443 (HTTP.sys). Aktivieren Sie Require Server Name Indication an der IIS-Bindung (New-WebBinding … -SslFlags 1), sonst behindern sich IIS und AD FS gegenseitig.
  6. Der Hub benötigt weder preserveHostHeader noch X-Forwarded-Proto: Seine Adressen kommen aus redirect_uri in hub.json.

Der Hub vertraut X-Forwarded-For (das ARR hinzufügt) nur von einem Proxy auf demselben Computer. Das Audit-Protokoll und die Sperre bei falschen Tokens sehen dann die tatsächliche Clientadresse.

Prüfung: Von einem Arbeitsplatz aus zeigt https://hub.company.com/ die Anmeldeseite ohne Zertifikatswarnung.

8. Schritt 6 – Firmenanmeldung (AD FS oder Entra ID)

AD FS

  1. AD FS Management → Application Groups → Add, dann die Vorlage Server application accessing a web API, Name „Compass Hub“.
  2. Server application:
    • notieren Sie die Client-ID (client identifier);
    • Umleitungs-URI: https://hub.company.com/auth/callback;
    • Anmeldeinformationen: Generate a shared secret. Speichern Sie es sofort in C:\CompassHub\secrets\oidc_client_secret; AD FS zeigt es nur einmal an.
  3. Web API:
    • Bezeichner: die Client-ID aus dem vorherigen Schritt;
    • Zugriffssteuerungsrichtlinie: die Personen, die den Hub nutzen dürfen, z. B. „Permit everyone“ (die Rollen kommen weiterhin aus den Gruppen);
    • zulässige Bereiche (Scopes): openid, profile, email, allatclaims.
  4. Web API → Issuance Transform Rules → „Send LDAP Attributes as Claims“ (Active Directory):
    • User-Principal-Name → upn;
    • E-Mail-Addresses → email;
    • Display-Name → name;
    • Token-Groups - Unqualified Names → groups.
    (Geben Sie die Namen der ausgehenden Claims genau so ein.)

In hub.json (der Hub fügt allatclaims für AD FS selbst hinzu, damit die Claims in das ID-Token gelangen):

"oidc": {
  "issuer": "https://adfs.company.com/adfs",
  "client_id": "<client identifier>",
  "redirect_uri": "https://hub.company.com/auth/callback",
  "groups_claim": "groups",
  "roles": { "admin": ["Compass-Admins"], "architect": ["Compass-Architects"], "viewer": ["Compass-Viewers"] },
  "password_login": true
}

Microsoft Entra ID

Die Konfiguration in Entra ID:

  • App-Registrierung: Plattform Web, Umleitungs-URI https://hub.company.com/auth/callback, ein Clientgeheimnis (in die Geheimnisdatei) und das ID-Token mit den optionalen Claims upn und email.
  • Aussteller (Issuer): https://login.microsoftonline.com/<tenant-id>/v2.0.
  • Gruppen: Entra sendet sie standardmäßig als Objekt-IDs. Tragen Sie entweder diese IDs in roles ein, oder wählen Sie für aus AD synchronisierte Gruppen „sAMAccountName“ in der Tokenkonfiguration.

Regeln, die der Hub anwendet

  • Die Rolle ergibt sich bei jeder Anmeldung aus den Gruppen, und die höchste gilt. Eine Person, die in keiner der Gruppen ist, erhält keinen Zugang.
  • Ein Firmenkonto mit demselben Namen wie ein lokaler Hub-Benutzer wird abgelehnt, bis der lokale Benutzer umbenannt oder entfernt ist.
  • Der Hub prüft das ID-Token selbst: die RS256-Signatur, Aussteller, Zielgruppe, Ablauf und Nonce, mit PKCE und einem einmaligen State.
  • Wenn alles funktioniert, setzen Sie "password_login": false: Dann bleibt nur die Schaltfläche für die Firmenanmeldung. API-Tokens für MCP-Clients funktionieren weiterhin. Bewahren Sie ein lokales Admin-Kennwort in Ihrem Kennworttresor auf, für den Fall, dass der Identitätsanbieter ausfällt.

Prüfung: Nach Restart-Service CompassHub führt „Mit dem Firmenkonto anmelden“ zu AD FS und zurück. hub.log zeigt „… signed in with a company account as architect“, und die Registerkarte Users listet das Firmenkonto mit seiner Rolle auf.

9. Schritt 7 – KI-Schlüssel, Jira, Confluence und die Teamrichtlinie

Fügen Sie die Abschnitte in hub.json ein. Jedes hier genannte Geheimnis benötigt außerdem seine Variable …_FILE (Schritt 3). Führen Sie dann Restart-Service CompassHub aus; angemeldete Personen bleiben angemeldet.

"ai": {
  "keys":   [ { "for": "role:architect", "secret": "claude_key_team" },
              { "for": "anna@company.com", "secret": "claude_key_anna" } ],
  "limits": [ { "for": "*", "tokens_per_day": 2000000, "tokens_per_month": 30000000 } ],
  "models": [ "claude-haiku-5-5", "claude-sonnet-5-5" ]
},
"integrations": {
  "jira":       { "url": "https://company.atlassian.net", "user": "svc-compass@company.com", "project": "ARCH", "issue_type": "Task" },
  "confluence": { "url": "https://company.atlassian.net/wiki", "user": "svc-compass@company.com", "space": "ARCH" }
},
"policy": {
  "min_approval": "ask",
  "ai_via_hub": true,
  "jira_via_hub": true,
  "confluence_via_hub": true,
  "web_access": false,
  "update_check": false
}
EinstellungBedeutung
ai.keysWelchen Claude-Schlüssel eine Person verwendet. Reihenfolge: der Benutzername, dann role:<role>, dann *. Ohne Treffer gibt es für diese Person keine KI.
ai.limitsTokens pro Tag und pro Monat. Oberhalb des Limits lehnt der Hub mit einer klaren Meldung ab.
ai.modelsDie erlaubten Modelle; andere Modelle werden abgelehnt.
policy.ai_via_hubCompass fragt die KI nur über den Hub: kein API-Schlüssel auf den Arbeitsplätzen.
policy.jira_via_hub, confluence_via_hubJira/Confluence über das Dienstkonto des Hubs. Die Rolle viewer darf nur lesen; jede Änderung wird protokolliert.
policy.min_approvalDer schwächste Freigabemodus, der in Compass für Schreibvorgänge im Modell erlaubt ist (ask ist der strengste).
policy.web_access, web_allowed_domainsOb der Assistent im Web suchen oder Seiten lesen darf, und von welchen Domänen.
policy.update_checkOb Compass stündlich auf GitHub nach einer neuen Version sucht.

Administratoren ändern die Richtlinie später auf der Registerkarte Team policy der Weboberfläche, und die Nutzung pro Person steht unter Users → AI usage.

10. Schritt 8 – Die Arbeitsplätze (Gruppenrichtlinien)

  1. Dem Zertifikat vertrauen. Wenn das Hub-Zertifikat von der firmeneigenen CA stammt, verteilen Sie deren Stammzertifikat an die Arbeitsplätze (GPO: Computerkonfiguration → Richtlinien → Windows-Einstellungen → Sicherheitseinstellungen → Richtlinien für öffentliche Schlüssel → Vertrauenswürdige Stammzertifizierungsstellen). Ohne dieses meldet Compass ein nicht vertrauenswürdiges Zertifikat (UnknownIssuer).
  2. Vorlagen. Kopieren Sie LoonarCompass.admx nach \\<domain>\SYSVOL\<domain>\Policies\PolicyDefinitions und en-US\LoonarCompass.adml (bei Bedarf auch pl-PL) in die Sprachunterordner. Ohne zentralen Speicher kopieren Sie sie nach C:\Windows\PolicyDefinitions auf dem Computer, auf dem Sie das GPO bearbeiten.
  3. GPO für die OU der Arbeitsplätze: Computerkonfiguration → Administrative Vorlagen → Loonar → Loonar Compass.

Compass installieren. Stille Deinstallation: "C:\Program Files\Loonar Compass\uninstall.exe" --uninstall --quiet.

Die erste Anmeldung des Benutzers. Öffnen Sie in Compass Einstellungen → Team (Compass Hub) → Mit dem Firmenkonto anmelden. Der Browser öffnet AD FS und kehrt zu Compass zurück. Die Anmeldung gilt 12 Stunden und übersteht einen Neustart des Hubs.

Die Firmenanmeldung endet bei https://hub.company.com/adfs/… oder mit 404ARR schreibt die Weiterleitung um. Setzen Sie reverseRewriteHostInResponseHeaders = False (Schritt 5).

14. Linux und Docker

Derselbe Hub läuft in einem Container. Der Datenordner (hub.json mit "listen": "0.0.0.0:8730", die Modelle und die Dateien des Hubs) wird als /data eingebunden und muss für den Benutzer 10001 beschreibbar sein. Die Geheimnisse kommen aus Variablen LOONAR_SECRET_* oder aus Docker Secrets über LOONAR_SECRET_*_FILE:

docker run -d --name compass-hub -p 127.0.0.1:8730:8730 -v /srv/compass-hub:/data \
  -e LOONAR_SECRET_CLAUDE_KEY_TEAM_FILE=/run/secrets/claude_key_team \
  ghcr.io/loonar-eu/compass-hub:0.9.0

Stellen Sie nginx oder einen anderen HTTPS-Proxy davor, wie in Schritt 5. Der Proxy muss den Header Location von Weiterleitungen unverändert lassen, X-Forwarded-For weitergeben sowie Anfragekörper von 32 MB und ein Timeout von 5 Minuten erlauben. Für Modelle in SQL Server, MySQL oder Oracle bauen Sie ein eigenes Image auf Basis dieses Images und fügen den Linux-ODBC-Treiber des Herstellers hinzu.
