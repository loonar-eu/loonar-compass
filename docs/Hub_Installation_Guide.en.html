1. What you install

Compass Hub is the team service of Loonar Compass. It is one program, compass-hub.exe, without an installer and without Enterprise Architect. It runs as a Windows service and keeps:

  • the team's EA models (read only): .qea/.qeax files or a PostgreSQL, SQL Server, MySQL or Oracle repository;
  • the team policy, which the Compass apps follow: the minimum approval mode, web access, the AI only through the hub, and so on;
  • the audit trail of the changes from all workstations, the change sets for review, and a web view for people without EA;
  • the AI gateway: the Claude API keys stay on the server, with a key and limits per person or role;
  • Jira and Confluence through one service account, a read-only GraphQL API, tables for Power BI and an MCP server.

This is the setup tested end to end on Windows Server 2022 with AD, AD CS, AD FS and IIS. Each step ends with a check, so a problem shows up at the step that caused it.

3. Step 1 – Files and folder

  1. Check the SHA-256 of the download against the value published with the release: 
    Get-FileHash .\CompassHub-0.9.0-windows-x64.zip -Algorithm SHA256
  2. Unpack it to C:\CompassHub and create the subfolders models and secrets.
  3. Restrict the folder to the service and the administrators. The hub writes its data here, and the secrets are here: 
    icacls C:\CompassHub /inheritance:r /grant:r "SYSTEM:(OI)(CI)F" "BUILTIN\Administrators:(OI)(CI)F"
    On a Windows in another language, use the SID *S-1-5-32-544 instead of the name of the Administrators group.

Check: C:\CompassHub\compass-hub.exe --version prints 0.9.0.

4. Step 2 – hub.json and the models

Copy hub.example.json to C:\CompassHub\hub.json. A minimal start:

{
  "listen": "127.0.0.1:8730",
  "sources": [
    { "id": "architecture", "name": "Enterprise architecture", "properties": "models/architecture.properties" }
  ],
  "policy": { "min_approval": "ask" }
}
  • listen stays on 127.0.0.1: only IIS on the same server talks to the hub.
  • sources: one entry per model. id is short and stable, because the users and Power BI use it. properties is relative to hub.json.
  • Leave out users: the hub then creates the account admin (step 4) and writes users back itself, as hashes only.

The model file, e.g. C:\CompassHub\models\architecture.properties:

# An EA project file (read only)
model.source=file
model.file=C:/CompassHub/models/Architecture.qea

# ... or a repository database (the password is the secret DB_PASSWORD):
# model.source=sqlserver          (or postgres, mysql, oracle)
# db.host=sql.company.com
# db.port=1433
# db.name=ea_repository
# db.user=compass_reader
# db.sslmode=verify-full

SQL Server, MySQL and Oracle are read through the vendor's 64-bit ODBC driver, which must be installed on the server (e.g. "ODBC Driver 18 for SQL Server"). PostgreSQL and files need nothing more. Every read is rolled back, so a read-only database account is enough.

Keep the hub's model files separate from the files people edit in EA. To refresh a file model, replace the file. The hub opens it read-only for each request, so no restart is needed.

5. Step 3 – Secrets

Each secret is a text file in C:\CompassHub\secrets that contains only the value. The service learns the path from an environment variable LOONAR_SECRET_<NAME>_FILE. The person who knows the value creates the file, e.g. in Notepad or with:

Read-Host -AsSecureString "Value" | ConvertFrom-SecureString -AsPlainText | Set-Content C:\CompassHub\secrets\claude_key_team -NoNewline

(-AsPlainText needs PowerShell 7; in Windows PowerShell 5.1, Notepad is simpler.)

File (example)Variable for the serviceNeeded for
claude_key_teamLOONAR_SECRET_CLAUDE_KEY_TEAM_FILEThe AI gateway: one variable per key named in hub.json (step 7)
claude_api_keyLOONAR_SECRET_CLAUDE_API_KEY_FILE"Ask" in the web view
jira_tokenLOONAR_SECRET_JIRA_TOKEN_FILEJira
confluence_tokenLOONAR_SECRET_CONFLUENCE_TOKEN_FILEConfluence
oidc_client_secretLOONAR_SECRET_OIDC_CLIENT_SECRET_FILECompany sign-in
db_passwordLOONAR_SECRET_DB_PASSWORD_FILEA model database

The name in the variable is the secret name in capitals, with other characters as _: the hub.json secret claude_key_anna is LOONAR_SECRET_CLAUDE_KEY_ANNA_FILE.

The variables are set on the service only, not for the whole computer, after the service is installed (step 4). This takes effect at the next start of the service, with no reboot:

$vars = @(
  'LOONAR_SECRET_CLAUDE_KEY_TEAM_FILE=C:\CompassHub\secrets\claude_key_team',
  'LOONAR_SECRET_JIRA_TOKEN_FILE=C:\CompassHub\secrets\jira_token',
  'LOONAR_SECRET_CONFLUENCE_TOKEN_FILE=C:\CompassHub\secrets\confluence_token',
  'LOONAR_SECRET_OIDC_CLIENT_SECRET_FILE=C:\CompassHub\secrets\oidc_client_secret'
  # 'HTTPS_PROXY=http://proxy.company.com:8080'   only if the server goes out through a proxy
)
Set-ItemProperty HKLM:\SYSTEM\CurrentControlSet\Services\CompassHub -Name Environment -Type MultiString -Value $vars
Restart-Service CompassHub

The hub reads a secret when it first needs it. A missing one is reported where it is used, e.g. "secret 'jira_token' is not set: give it as LOONAR_SECRET_JIRA_TOKEN (or a file named in LOONAR_SECRET_JIRA_TOKEN_FILE)". The values never appear in hub.json, the logs or the web view.

6. Step 4 – The Windows service and the first sign-in

  1. In PowerShell as administrator: 
    C:\CompassHub\compass-hub.exe --service-install C:\CompassHub\hub.json
    This creates the service CompassHub ("Compass Hub (Loonar Compass team service)"), with automatic start under LocalSystem, and starts it.
  2. Now set the secrets of the service (step 3) and run Restart-Service CompassHub.
  3. On the server, open http://127.0.0.1:8730/ and sign in as admin / passw0rd (with a zero). The hub asks for a new password at once and allows nothing else until then. The password needs at least 10 characters. Do this before step 5 makes the hub reachable.

Check:

  • Get-Service CompassHub shows Running;
  • C:\CompassHub\hub.log shows the start and your sign-in;
  • the web view lists the model from step 2.

7. Step 5 – HTTPS with IIS (URL Rewrite + ARR)

The hub speaks plain HTTP on 127.0.0.1. IIS gives it the company name and certificate.

  1. Install IIS with URL Rewrite and ARR. Create a site, e.g. CompassHub, with a binding for https, port 443, the host name hub.company.com and the certificate. The physical path is an empty folder, e.g. C:\inetpub\compasshub.
  2. Turn on the proxy and switch off rewriting the host in redirects. This is required; otherwise ARR rewrites the redirect to AD FS to the hub's own address, and the company sign-in fails. Set the timeout for long AI answers as well: 
    Import-Module WebAdministration
$p = 'MACHINE/WEBROOT/APPHOST'
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name enabled -Value True
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name reverseRewriteHostInResponseHeaders -Value False
Set-WebConfigurationProperty -PSPath $p -Filter system.webServer/proxy -Name timeout -Value '00:05:00'
  3. Put this web.config in the site folder. It forwards everything to the hub and allows request bodies up to 32 MB, because questions with model diagrams are large: 
    <?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="CompassHub" stopProcessing="true">
          <match url="(.*)" />
          <action type="Rewrite" url="http://127.0.0.1:8730/{R:1}" />
        </rule>
      </rules>
    </rewrite>
    <security>
      <requestFiltering>
        <requestLimits maxAllowedContentLength="33554432" />
      </requestFiltering>
    </security>
  </system.webServer>
</configuration>
  4. Firewall: allow inbound 443 only. Port 8730 is never opened, because the hub listens on 127.0.0.1.

The hub trusts X-Forwarded-For (which ARR adds) only from a proxy on the same computer. The audit trail and the lockout of wrong tokens then see the real client address.

Check: from a workstation, https://hub.company.com/ shows the sign-in page with no certificate warning.

8. Step 6 – Company sign-in (AD FS or Entra ID)

AD FS

  1. AD FS Management → Application Groups → Add, then the template Server application accessing a web API, name "Compass Hub".
  2. Server application:
    • note the client identifier;
    • redirect URI: https://hub.company.com/auth/callback;
    • credentials: Generate a shared secret. Save it right away into C:\CompassHub\secrets\oidc_client_secret; AD FS shows it only once.
  3. Web API:
    • identifier: the client identifier from the previous step;
    • access control policy: the people who may use the hub, e.g. "Permit everyone" (roles still come from the groups);
    • permitted scopes: openid, profile, email, allatclaims.
  4. Web API → Issuance Transform Rules → "Send LDAP Attributes as Claims" (Active Directory):
    • User-Principal-Name → upn;
    • E-Mail-Addresses → email;
    • Display-Name → name;
    • Token-Groups - Unqualified Names → groups.
    (Type the outgoing claim names exactly like that.)

In hub.json (the hub adds allatclaims for AD FS itself, so the claims reach the ID token):

"oidc": {
  "issuer": "https://adfs.company.com/adfs",
  "client_id": "<client identifier>",
  "redirect_uri": "https://hub.company.com/auth/callback",
  "groups_claim": "groups",
  "roles": { "admin": ["Compass-Admins"], "architect": ["Compass-Architects"], "viewer": ["Compass-Viewers"] },
  "password_login": true
}

Microsoft Entra ID

The setup in Entra ID:

  • App registration: platform Web, redirect URI https://hub.company.com/auth/callback, a client secret (into the secret file), and the ID token with the optional claims upn and email.
  • Issuer: https://login.microsoftonline.com/<tenant-id>/v2.0.
  • Groups: Entra sends them as object IDs by default. Either put those IDs in roles, or, for groups synchronised from AD, choose "sAMAccountName" in the token configuration.

Rules the hub applies

  • The role comes from the groups at every sign-in, and the highest one wins. A person in none of the groups gets no access.
  • A company account with the same name as a local hub user is refused until the local user is renamed or removed.
  • The hub checks the ID token itself: the RS256 signature, issuer, audience, expiry and nonce, with PKCE and a one-time state.
  • When everything works, set "password_login": false: only the company button remains. API tokens for MCP clients still work. Keep one local admin password in your vault, for the case that the identity provider is down.

Check: after Restart-Service CompassHub, "Sign in with your company account" leads to AD FS and back. hub.log shows "… signed in with a company account as architect", and the Users tab lists the company account with its role.

9. Step 7 – AI keys, Jira, Confluence and the team policy

Add the sections to hub.json. Every secret named here also needs its …_FILE variable (step 3). Then run Restart-Service CompassHub; the signed-in people stay signed in.

"ai": {
  "keys":   [ { "for": "role:architect", "secret": "claude_key_team" },
              { "for": "anna@company.com", "secret": "claude_key_anna" } ],
  "limits": [ { "for": "*", "tokens_per_day": 2000000, "tokens_per_month": 30000000 } ],
  "models": [ "claude-haiku-5-5", "claude-sonnet-5-5" ]
},
"integrations": {
  "jira":       { "url": "https://company.atlassian.net", "user": "svc-compass@company.com", "project": "ARCH", "issue_type": "Task" },
  "confluence": { "url": "https://company.atlassian.net/wiki", "user": "svc-compass@company.com", "space": "ARCH" }
},
"policy": {
  "min_approval": "ask",
  "ai_via_hub": true,
  "jira_via_hub": true,
  "confluence_via_hub": true,
  "web_access": false,
  "update_check": false
}
SettingMeaning
ai.keysWhich Claude key a person uses. Order: the user name, then role:<role>, then *. No match means no AI for that person.
ai.limitsTokens per day and per month. Above the limit, the hub refuses with a clear message.
ai.modelsThe allowed models; other models are refused.
policy.ai_via_hubCompass asks the AI only through the hub: no API key on the workstations.
policy.jira_via_hub, confluence_via_hubJira/Confluence through the service account of the hub. A viewer may only read; every change is audited.
policy.min_approvalThe weakest approval mode allowed in Compass for writes to the model (ask is the strictest).
policy.web_access, web_allowed_domainsWhether the assistant may search the web or read pages, and from which domains.
policy.update_checkWhether Compass checks GitHub once a day for a new version.

Admins change the policy later in the Team policy tab of the web view, and the usage per person is in Users → AI usage.

10. Step 8 – The workstations (Group Policy)

  1. Trust the certificate. If the hub certificate comes from the company CA, deploy its root to the workstations (GPO: Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities). Without it, Compass reports an untrusted certificate (UnknownIssuer).
  2. Templates. Copy LoonarCompass.admx to \\<domain>\SYSVOL\<domain>\Policies\PolicyDefinitions, and en-US\LoonarCompass.adml (and pl-PL if needed) to the language subfolders.
  3. GPO for the workstation OU: Computer Configuration → Administrative Templates → Loonar → Loonar Compass.
PolicyRegistry value (HKLM\SOFTWARE\Policies\Loonar\Compass)Effect
Hub addressHubUrl (text)The hub address is fixed in Compass and cannot be changed.
Require the hubRequireHub = 1The assistant works only while the person is signed in to the hub.
Web accessWebAccess = 0No web search and no reading of pages; the 🌐 button is disabled.
Update checkUpdateCheck = 0No daily check for a new version.
Minimum approval modeMinApproval = ask / plan / autoA weaker mode cannot be chosen.
Allowed AI providersAllowedProviders, e.g. anthropicOther providers (e.g. OpenAI) are refused.

Without a domain, the same values can be imported with LoonarCompass-company-policy.reg (and removed with LoonarCompass-remove-policy.reg). The computer policy is stronger than the hub policy and the user's settings; it can only make Compass stricter.

Installing Compass. LoonarCompass-Setup-0.9.exe installs for the current user (%LOCALAPPDATA%\Programs\Loonar Compass) or for all users (Program Files), and registers the add-in in Enterprise Architect. For deployment tools (Intune, Configuration Manager, a startup script) it installs without a window:

LoonarCompass-Setup-0.9.exe --quiet --all-users
OptionEffect
--quietNo window and no questions. Exit code 0 = installed, 1 = error, 740 = --all-users without administrator rights. The result is in %TEMP%\LoonarCompass-Setup.log (for SYSTEM: C:\Windows\Temp).
--all-usersFor everybody: Program Files, the common Start menu, the add-in in EA for all users (HKLM). Run it as SYSTEM or as an administrator.
--dir <folder>Another program folder.
--lang en|pl|de|frThe language of the licence and changelog files.
--no-desktop, --no-start-menuWithout these shortcuts.
--no-ea-addinWithout the add-in in Enterprise Architect.

The same command updates an existing installation. Close Compass and EA on the computer first. The user settings are not touched; with the computer policy (hub address, required hub) nobody needs to configure anything. Quiet removal: "C:\Program Files\Loonar Compass\uninstall.exe" --uninstall --quiet.

The user's first sign-in. In Compass, open Settings → Team (Compass Hub) → Sign in with your company account. The browser opens AD FS and returns to Compass. The sign-in lasts 12 hours and survives a restart of the hub.

12. Operation: update, backup, logs, removal

Update

Stop-Service CompassHub
Copy-Item .\compass-hub.exe C:\CompassHub\compass-hub.exe -Force   # from the new zip, after checking its SHA-256
Start-Service CompassHub

hub.json, the secrets and the sign-ins stay as they are. People remain signed in.

What to back up (C:\CompassHub)

File / folderContent
hub.jsonConfiguration, local users (password and token hashes only), policy
audit.jsonlThe audit trail of changes and sign-ins
changes\, notes\Change sets for review and the team notes
ai_usage.jsonlAI usage per person (the base of the limits)
company_accounts.json, sessions.jsonCompany accounts seen and current sign-ins (hashes); can be lost without harm: people sign in again
secrets\Only if your backup is encrypted. Otherwise keep the values in the password vault.
models\The model files, if they are not kept elsewhere

Logs

  • hub.log: start, sign-ins, refused requests, errors. An "internal error (id …)" shown to a user has its details here under the same id.
  • audit.jsonl and hub.log are renamed with a date when they grow large.

Removal

C:\CompassHub\compass-hub.exe --service-uninstall

Then remove the IIS site, the AD FS application group and the GPO, and delete C:\CompassHub after the backup.

13. Troubleshooting

SymptomCause and fix
Compass: certificate not trusted / UnknownIssuer; the browser shows "Not secure"The workstation does not trust the root of the hub certificate. Deploy the root CA (step 8), then restart the browser and Compass.
Company sign-in ends at https://hub.company.com/adfs/… or with 404ARR rewrites the redirect. Set reverseRewriteHostInResponseHeaders = False (step 5).
"<name> is not in any group of the hub (…): ask the administrator for access"The person is in none of the role groups, or the groups claim is missing. Check the transform rule "Token-Groups - Unqualified Names → groups" and the allatclaims scope.
"A local user of the hub has the same name"Rename or remove that local user in the Users tab.
Compass: "the team hub or the server in front of it does not answer properly (502)"The service is stopped or starting: Get-Service CompassHub, then hub.log.
Compass: "your sign-in to the team hub has expired"12 hours have passed, or sessions.json was lost. Sign in again in Settings → Team.
"the hub has no AI key for you"No ai.keys entry for the person, their role or *.
"your AI limit for today is used up"Raise ai.limits for the person or role, or wait for the next day.
"secret '…' is not set: give it as LOONAR_SECRET_…"The …_FILE variable is missing in the service's Environment, or the file is empty or not readable by SYSTEM.
hub.log: "<address>: 20 wrong tokens, refused for 10 minutes"20 different wrong tokens came from one address (an old token repeated counts once). Valid tokens still work. Find the client in hub.log.

14. Linux and Docker

The same hub runs in a container. The data folder (hub.json with "listen": "0.0.0.0:8730", the models and the hub's files) is mounted as /data and must be writable by user 10001. The secrets come from LOONAR_SECRET_* variables or from Docker secrets through LOONAR_SECRET_*_FILE:

docker run -d --name compass-hub -p 127.0.0.1:8730:8730 -v /srv/compass-hub:/data \
  -e LOONAR_SECRET_CLAUDE_KEY_TEAM_FILE=/run/secrets/claude_key_team \
  ghcr.io/loonar-eu/compass-hub:0.9.0

Put nginx or another HTTPS proxy in front of it, as in step 5. The proxy must keep the Location header of redirects unchanged, pass X-Forwarded-For, allow 32 MB bodies and a 5-minute timeout. For SQL Server, MySQL or Oracle models, build your own image on this one and add the vendor's Linux ODBC driver.
