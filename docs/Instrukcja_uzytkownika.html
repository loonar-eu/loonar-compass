1. Czym jest Loonar Compass

Loonar Compass to samodzielna aplikacja okienkowa dla Windows: asystent AI do pracy z modelem Enterprise Architect (Sparx Systems). Piszesz do niego zwykłym językiem, a on:

  • czyta model (pakiety, elementy, diagramy, połączenia, atrybuty i operacje) i opisuje, co w nim jest,
  • analizuje model: wpływ zmiany elementu na resztę modelu, miejsca użycia operacji, elementy bez połączeń,
  • zmienia model: tworzy pakiety, diagramy, elementy i połączenia, dodaje atrybuty i operacje, ustawia wartości tagów i słowa kluczowe, rozmieszcza elementy na diagramach, przenosi je, zdejmuje z diagramu, usuwa, koloruje, dodaje legendy, kopiuje pakiety i robi ich baseline,
  • prowadzi słownik projektu EA (pojęcia z definicją i typem) oraz scenariusze elementów (kroki aktora i systemu),
  • rysuje diagramy z opisu, ze zdjęcia, ze szkicu albo z załączonego pliku,
  • pokazuje diagramy jako obrazki na czacie, tak jak rysuje je Enterprise Architect,
  • przygotowuje dokumenty z treści modelu: Word, Excel, PowerPoint, PDF, obrazki PNG i strony Confluence, także według szablonów,
  • czyta dokumenty: PDF, Word, PowerPoint, Visio i Excel, z Twojego dysku albo z biblioteki SharePoint zespołu,
  • stosuje instrukcje modelowania zespołu zapisane w samym repozytorium EA, więc każdy, kto pracuje z repozytorium, korzysta z tych samych reguł,
  • pamięta ustalenia między rozmowami (konwencje modelowania, preferencje, poprawki).

Aplikacja korzysta przez Internet z modelu językowego AI, z Twoim kluczem API: domyślnie z Claude Haiku 5.5 (Anthropic), a w ustawieniach możesz wybrać inny model Claude albo model OpenAI (rozdział 5). Z modelem EA łączy się na dwa sposoby: czyta go wprost (z bazy PostgreSQL, SQL Server, MySQL/MariaDB albo Oracle albo z pliku .qea/.qeax), a zapisuje przez Enterprise Architect, na koncie użytkownika modelu podanym w ustawieniach, jeśli model ma takie konto. Gdy plik modelu masz otwarty w EA, zmiany idą przez Twoje okno EA; w pozostałych przypadkach EA działa w tle. Zmiany w modelu możesz przed zapisem zatwierdzić albo odrzucić (rozdział 16).

Loonar Compass działa jako osobne okno, uruchamiane z menu Start, albo jako okno zadokowane w samym Enterprise Architect, które pracuje na projekcie otwartym w tym oknie EA (rozdział 10).

Interfejs i odpowiedzi asystenta są dostępne w czterech językach: polskim, angielskim, niemieckim i francuskim (rozdział 5). Aplikacja jest bezpłatna, także do użytku komercyjnego (rozdział 24).

Bez okna Compass sprawdza też model w potokach CI (rozdział 23), a osobny program Compass Hub udostępnia modele zespołu ludziom i narzędziom (rozdział 22).

2. Wymagania

Warunki konieczne. Obsługiwana konfiguracja wymaga spełnienia następujących warunków:
  1. Model jest plikiem projektu EA .qea lub .qeax albo jest w bazie danych PostgreSQL, SQL Server, MySQL/MariaDB albo Oracle. Starsze formaty plików (.eap, .eapx, .feap) nie są obsługiwane; plik .eap/.eapx Enterprise Architect przekonwertuje do .qea transferem projektu (Settings → Model → Transfer → Full Project Transfer).
  2. Model w bazie ma włączone zabezpieczenia użytkowników (w Enterprise Architect: Settings → Security → Enable Security), w trybie „Require User Lock to Edit”. W pliku modelu zabezpieczenia są opcjonalne: bez nich asystent nie potrzebuje konta EA. Aplikacja loguje się do modelu na konto asystenta i na czas zapisu zakłada blokady. Gdy zabezpieczenia są wyłączone, blokady są pomijane, a taka konfiguracja nie jest obsługiwana. W aplikacji zaznaczasz to w karcie Model ustawień opcjami „Model ma włączone zabezpieczenia (konta użytkowników EA)” i „Model wymaga blokady do edycji (Require User Lock to Edit)” (rozdział 5).
  3. W modelu z włączonymi zabezpieczeniami istnieje konto użytkownika dla asystenta (Settings → Security → Users), z hasłem i z uprawnieniami do edycji. Nazwa konta jest dowolna, na przykład claude albo asystent. Login i hasło tego konta podajesz w karcie Model ustawień, razem z plikiem albo bazą modelu.

3. Instalacja

Uruchom plik LoonarCompass-Setup-0.9.exe. Kreator prowadzi przez kolejne strony przyciskami Dalej i Wstecz. Uprawnień administratora nie potrzebujesz, chyba że instalujesz aplikację dla wszystkich użytkowników komputera.

Ostrzeżenie Windows SmartScreen. Instalator nie jest jeszcze podpisany cyfrowo, dlatego przy pierwszym uruchomieniu Windows może pokazać komunikat „System Windows ochronił ten komputer”. Kliknij Więcej informacji, a potem Uruchom mimo to. Gdy w systemie jest włączona Inteligentna kontrola aplikacji (Smart App Control), Windows blokuje niepodpisane aplikacje bez możliwości ich uruchomienia: poczekaj wtedy na wersję podpisaną. Instalator pobieraj tylko z loonar.eu albo z wydań projektu na GitHubie.
  1. Język. Polski, angielski, niemiecki albo francuski. Przy nowej instalacji zaznaczony jest angielski, a przy aktualizacji język zapisany w Twoich ustawieniach. Wybrany język dotyczy kreatora, aplikacji, odpowiedzi asystenta i domyślnych szablonów dokumentów; później zmienisz go w ustawieniach (rozdział 5).
  2. Powitanie. Warunki konieczne i lista rzeczy, które warto przygotować przed instalacją.
  3. Co nowego. Przy aktualizacji: zmiany od zainstalowanej wersji. Przy nowej instalacji: najważniejsze zmiany w bieżącej wersji.
  4. Umowa licencyjna. Zaznacz „Akceptuję warunki umowy licencyjnej”.
  5. Folder docelowy. Rodzaj instalacji (opisany niżej), folder programu i skróty: w menu Start (aplikacja, instrukcja użytkownika, odinstalowanie) i na pulpicie. Opcja „Dodaj Loonar Compass do Enterprise Architect” instaluje Compass w EA (rozdział 10); po instalacji uruchom EA ponownie.
  6. Konfiguracja. Wybierz „Podam dane teraz” albo „Skonfiguruję później w aplikacji (widok »Ustawienia«)”. Od razu możesz podać klucz API Claude (pod polem jest informacja, co trafia do Anthropic; dostawcę OpenAI wybierzesz później w ustawieniach), model (bazę PostgreSQL: serwer, port, nazwa bazy, konto i hasło do bazy, albo plik EA: ścieżka do pliku .qea/.qeax, którą wybierzesz przyciskiem …), ścieżkę do EA.exe (przycisk … otwiera wybór pliku), konto i hasło użytkownika EA oraz tryb zatwierdzania zmian. Puste pole hasła lub klucza zostawia wartość zapisaną wcześniej.
  7. Gotowy do instalacji. Podsumowanie wyborów. Kliknij Instaluj; pasek postępu pokazuje procent i bieżący krok.
  8. Zakończenie. Zaznaczona opcja „Uruchom Loonar Compass” otwiera aplikację po kliknięciu Zakończ.

Rodzaj instalacji

Na stronie „Folder docelowy” wybierasz, dla kogo instalujesz aplikację:

  • „Tylko dla mnie (zalecane, bez uprawnień administratora)”: program trafia do folderu %LOCALAPPDATA%\Programs\Loonar Compass. Windows nie prosi o uprawnienia administratora.
  • „Dla wszystkich użytkowników tego komputera (wymaga uprawnień administratora)”: program trafia do folderu %ProgramFiles%\Loonar Compass, w którym pliki mogą zmieniać tylko administratorzy. Windows prosi o uprawnienia administratora dopiero po kliknięciu Instaluj. Jeśli ich nie przyznasz, nic nie zostanie zainstalowane.

Ustawienia i hasła zawsze trafiają do profilu użytkownika, który uruchomił kreator, także wtedy, gdy uprawnienia administratora potwierdza inna osoba. Przy instalacji dla wszystkich użytkowników każdy z nich ma własne ustawienia, rozmowy i hasła.

Pasek zadań. Windows 11 nie pozwala instalatorom przypinać programów do paska zadań. Uruchom aplikację, kliknij jej ikonę na pasku prawym przyciskiem myszy i wybierz „Przypnij do paska zadań”.

Aktualizacja z wcześniejszej wersji

Wcześniejsze wersje aplikacji nosiły nazwę Loonar EA Assistant: Loonar Compass automatycznie przejmuje ich ustawienia, rozmowy, pamięć asystenta, szablony i hasła.

  • Wcześniejsza wersja zainstalowana tylko dla Ciebie jest usuwana podczas instalacji (pliki programu, skróty i wpis w ustawieniach Windows); Twoje dane zostają.
  • Wcześniejszą wersję zainstalowaną dla wszystkich użytkowników kreator pokazuje na stronie „Gotowy do instalacji”. Usuniesz ją przyciskiem Usuń starą wersję (uprawnienia administratora) albo później w ustawieniach Windows (Aplikacje). Twoje ustawienia i rozmowy zostają.
  • Na pierwszej stronie kreator zaznacza język zapisany w Twoich ustawieniach (ustawienia bez zapisanego języka oznaczają polski), a gdy ustawień nie ma, angielski. Sprawdź ten wybór, zanim klikniesz Dalej.
  • Zmiana języka w kreatorze nie tłumaczy pamięci asystenta ani szablonów. Jeśli chcesz je przenieść na nowy język, zostaw w kreatorze dotychczasowy język, a po instalacji zmień go w karcie „Język i zatwierdzanie zmian” ustawień (rozdział 5).
  • Hasło do bazy, które starsze wersje trzymały w pliku ustawień, trafia do Menedżera poświadczeń Windows, a pliki z polskimi nazwami w folderze danych dostają nazwy angielskie (na przykład audit_log.jsonl i templates).

SQL Server, MySQL i Oracle

Oprócz PostgreSQL i plików EA Compass czyta repozytoria EA w SQL Server, MySQL/MariaDB i Oracle: w osobnym oknie, w hubie zespołu (rozdział 22) i w trybie sprawdzania (rozdział 23). W karcie Model wybierz SQL Server, MySQL albo Oracle i wypełnij te same pola co dla PostgreSQL; port zmienia się na zwykły port tej bazy (1433, 3306, 1521), chyba że zmieniłeś go sam. Taką bazą może być też model rozmowy (rozdział 17).

  • Sterownik ODBC. Compass łączy się przez 64-bitowy sterownik ODBC producenta bazy i sam go znajduje. Dla SQL Server bierze „ODBC Driver 18 for SQL Server”, potem 17, a na końcu własny sterownik Windows „SQL Server”. Dla MySQL sterownik MySQL albo MariaDB, dla Oracle sterownik klienta Oracle („Oracle in …”). Gdy żadnego nie ma, test podaje zainstalowane sterowniki.
  • Własny ciąg połączenia. Gdy połączenie wymaga czegoś, czego nie ma w karcie (na przykład nazwy TNS Oracle albo opcji sterownika), wpisz w app.properties pełny ciąg połączenia ODBC jako db.odbc, bez hasła: Compass dodaje hasło z Menedżera poświadczeń. Przykład: db.odbc=Driver={ODBC Driver 18 for SQL Server};Server=sql01,1433;Database=ea;UID=compass;Encrypt=yes.
  • Tylko odczyt. Odczyt idzie w transakcji, która zawsze jest wycofywana, więc sam Compass niczego w bazie nie zmienia. Do odczytu wystarczy konto z prawem SELECT na tabelach EA (t_*); gdy Enterprise Architect zapisuje tym samym kontem (SQL Server, niżej), potrzebuje też INSERT, UPDATE i DELETE na tych tabelach.

Zapis. Zmiany takiego modelu zapisuje Enterprise Architect, tak jak przy PostgreSQL. Twoja edycja EA musi obsługiwać repozytoria DBMS.

  • SQL Server: Compass sam buduje połączenie EA (dostawca OLE DB SQLOLEDB) z pól karty Model. Sprawdź je przyciskiem „Zapisz i sprawdź dostęp do EA”.
  • MySQL i Oracle: EA łączy się z nimi przez źródło danych ODBC. Wpisz połączenie EA do app.properties jako ea.conn: tekst skrótu połączenia EA, na przykład ea_lab --- DBType=0;Connect=Provider=MSDASQL.1;Data Source=<DSN ODBC>;…. Bez ea.conn zmiany wprowadzaj przez Compassa w Enterprise Architect (rozdział 10): zapisuje on przez Twoje okno EA, które działa z każdym otwartym w nim repozytorium.

W app.properties wybór to model.source=sqlserver, mysql albo oracle (postgres i file jak dotąd), z db.host, db.port, db.name, db.user i db.sslmode.

W trakcie pracy asystenta

  • Pod wiadomościami widać kartę kroków: co asystent właśnie robi, ile to trwa i jaki był wynik każdego kroku. W trakcie pracy karta jest rozwinięta, a po zakończeniu zwija się do jednej linii; kliknięcie nagłówka karty rozwija ją ponownie.
  • W polskiej wersji interfejsu wynik kroku to krótkie podsumowanie, na przykład „wiersze: 12”, „zapisano w modelu EA” albo „plik gotowy”. Pełną treść wyniku (po angielsku) lista pokazuje tylko w angielskiej wersji interfejsu.
  • Możesz pisać dalej: kolejna wiadomość trafia do kolejki i asystent uwzględni ją przy najbliższym kroku, bez przerywania pracy.
  • Przycisk Przerwij zatrzymuje pracę po bieżącym kroku. Krok, który już trwa (na przykład zapis do EA), dobiega końca.
  • Jedna odpowiedź może mieć najwyżej 24 kroki. Jeśli asystent nie zdąży w tym limicie, przerywa pracę z komunikatem, że wykonał maksymalną liczbę kroków; poproś go wtedy w nowej wiadomości, żeby kontynuował.

Rozumowanie i obliczenia

Dwa przełączniki w karcie wiadomości działają tylko z Claude (przy OpenAI ich nie ma); ustawienie jest zapamiętywane.

  • 💭 Pokazuj rozumowanie asystenta w krokach. Streszczenie tego, jak model rozumuje, pojawia się w krokach jako „💭 Rozumowanie asystenta”. Model rozumuje tak czy inaczej; przełącznik tylko to pokazuje. Ile rozumuje, nadal decyduje poziom wysiłku w karcie Model AI (rozdział 5).
  • ∑ Kod w piaskownicy (domyślnie wyłączony). Asystent może uruchamiać kod w piaskownicy Anthropic do obliczeń i analizy danych, na przykład sum wyceny albo statystyk eksportu modelu. Wynik widać jako krok „Kod w piaskownicy”. Dane, które asystent tam przekazuje, trafiają do Anthropic, tak jak rozmowa (rozdział 18).
  • 🌐 Internet (domyślnie wyłączony). Asystent może szukać w internecie i czytać strony, np. dokumentację produktu albo artykuł, którego adres podajesz. Z Claude wyszukiwanie i czytanie stron wykonuje Anthropic. Z OpenAI Compass sam czyta tylko strony, których adresy podałeś w rozmowie (bez wyszukiwania); nie czyta adresów tego komputera ani sieci firmowej. Klucz claude.web_domains w ustawieniach (domeny po przecinku) zawęża dozwolone strony. Administrator huba może wyłączyć tę funkcję wszystkim ("web_access": false w polityce zespołu) albo ograniczyć domeny ("web_allowed_domains"). Każde wyszukiwanie i każda strona są widoczne w krokach odpowiedzi.

Kontrola jakości modelu

Jednym poleceniem asystent sprawdza pakiet razem z podpakietami. Sprawdzenie wykonuje program, a nie model AI, więc nic nie jest zgadywane. Wbudowane kontrole:

  • domyślne i puste nazwy (na przykład Class1, Activity 2),
  • elementy bez opisu,
  • osierocone elementy (bez relacji i na żadnym diagramie),
  • powtórzone nazwy w pakiecie i powtórzone relacje,
  • relacje elementu do samego siebie oraz do nieistniejących elementów,
  • relacje niedozwolone w ArchiMate 3.2 (opis niżej),
  • puste pakiety i puste diagramy.

Każde ustalenie ma wagę: błąd, ostrzeżenie albo informacja. Poprawki asystent wprowadza dopiero po Twojej zgodzie.

Sprawdź jakość pakietu Zamówienia.

Reguły organizacji. Własne reguły wpisujesz w pliku governance.json, który leży obok app.properties (pliku ustawień w folderze danych użytkownika). Gdy takiego pliku nie ma, a Compass jest połączony z hubem zespołu, reguły pochodzą z polityki zespołu (rozdział 22). Przykład:

{"naming":[{"applies_to":"Component","pattern":"*Service","message":"Nazwa komponentu kończy się na Service"}],
 "required_tags":[{"applies_to":"«ArchiMate_ApplicationComponent»","tag":"Owner"}],
 "allowed_relations":[{"connector_type":"Realisation","source":"Component","target":"Interface"}]}
  • naming: nazwy elementów danego typu muszą pasować do wzorca (pattern); message to treść ustalenia.
  • required_tags: element danego typu musi mieć wskazany tagged value.
  • allowed_relations: typ relacji wpisany na tej liście jest dozwolony tylko między wymienionymi końcami; typy relacji, których na liście nie ma, nie są ograniczane.

W applies_to podajesz typ elementu albo «stereotyp»; działają symbole wieloznaczne * i ?.

Relacje ArchiMate 3.2. Gdy relacja i oba jej końce mają stereotypy ArchiMate (na przykład «ArchiMate_ApplicationComponent», «ArchiMate_DataObject»), kontrola stosuje też reguły relacji ArchiMate 3.2, bez żadnej konfiguracji. Zgłasza tylko pewne naruszenia, jako błędy; połączeń, które mogłaby uzasadnić relacja wyprowadzona, nie zgłasza. Na przykład:

  • relacja access musi kończyć się na elemencie struktury pasywnej (obiekt biznesowy, obiekt danych, artefakt…) i zaczynać od elementu zachowania lub struktury aktywnej,
  • relacja influence musi kończyć się na elemencie motywacji,
  • relacje triggering, flow i serving nie łączą elementów struktury pasywnej ani elementów motywacji,
  • assignment prowadzi od struktury aktywnej do zachowania (albo od węzła do artefaktu),
  • specialization łączy dwa elementy tego samego typu,
  • element motywacji realizuje (realization) tylko inny element motywacji.

Węzły połączeń (junction) i grupowania (grouping) nie są sprawdzane. Kontrola na bieżąco w Compass w EA (rozdział 10) stosuje te same reguły. Reguły ArchiMate wyłączysz wpisem "archimate": false w governance.json.

Sprawdź w pakiecie Krajobraz aplikacji, które relacje są niedozwolone w ArchiMate 3.2.

Własne serwery MCP

Własne serwery MCP dają asystentowi dodatkowe narzędzia, na przykład system zgłoszeń, repozytorium albo firmową bazę wiedzy. Serwery wpisujesz w pliku mcp_servers.json obok pliku ustawień, a sprawdzasz w karcie Serwery MCP. Serwer może być programem lokalnym (command i args, komunikacja przez stdio) albo usługą HTTP (url i headers, Streamable HTTP):

{"servers":[{"name":"hub","url":"http://127.0.0.1:8730/mcp","headers":{"Authorization":"Bearer ${secret:hub_token}"}},
 {"name":"files","command":"npx","args":["-y","@modelcontextprotocol/server-filesystem","C:/docs"]}]}
  • ${secret:nazwa} to wpis w Menedżerze poświadczeń Windows, a ${env:NAZWA} to zmienna środowiska; dzięki temu tokeny nie leżą w pliku.
  • Każde wywołanie narzędzia pyta o Twoją zgodę, chyba że serwer ma "trusted": true. Ustawiaj to tylko dla serwerów, którym ufasz: to, że serwer sam deklaruje narzędzie jako tylko do odczytu, nie wystarcza.
  • Własnych kluczy i haseł Compassa (klucze dostawców AI, hasła i tokeny bazy, EA, Confluence, Jiry i Miro) nie można użyć w ${secret:…}. Jedyny wyjątek to ${secret:hub_token} w nagłówkach własnego punktu MCP huba zespołu (adres huba z Ustawień ze ścieżką /mcp), jak w przykładzie powyżej. Tokeny innych serwerów zapisz pod ich własnymi nazwami w Menedżerze poświadczeń Windows.
  • Program lokalny (command) dostaje tylko podstawowe zmienne środowiska Windows (PATH, TEMP, foldery profilu użytkownika, ustawienia proxy…) i zmienne wymienione w jego "env".
  • "command": "npx" działa: Compass uruchamia npx.cmd (tak samo npm, pnpm i yarn). Serwery uruchamiane przez npx wymagają Node.js na komputerze.
  • Logowanie inne niż nagłówek. Serwer HTTP może mieć "auth" zamiast nagłówka Authorization: {"type": "basic", "user": …, "password": …} dla nazwy użytkownika i hasła albo {"type": "oauth2", "token_url": …, "client_id": …, "client_secret": …, "scope": …} dla poświadczeń klienta OAuth2: Compass pobiera token z token_url i wysyła go jako Bearer. Hasła i klucze tajne trzymaj w Menedżerze poświadczeń jako ${secret:mcp_…}.
  • Przycisk Zapisz i sprawdź serwery MCP łączy się z każdym serwerem i pokazuje liczbę jego narzędzi.

Gotowe serwery. W karcie Serwery MCP wybierz serwer z listy Dodaj gotowy serwer i kliknij Dodaj: jego wpis trafia do tekstu mcp_servers.json, gdzie go uzupełniasz i zapisujesz kartę. Nazwa, która już jest użyta, dostaje numer.

Skrypty EA

Asystent pokazuje grupy skryptów i skrypty modelu, czyta skrypt, zapisuje skrypt (JScript, VBScript albo JavaScript; brakująca grupa powstaje sama) i go uruchamia. Zapis i uruchomienie skryptu wymagają zgody za każdym razem, także w trybie auto, bo skrypt może zmienić w modelu wszystko; panel zgody pokazuje cały kod. O czym warto wiedzieć

  • Pierwsze wywołanie EA trwa od kilku do kilkunastu sekund, bo aplikacja uruchamia Enterprise Architect w tle i otwiera model. Kolejne zapisy i pobrania diagramów trwają już krócej niż sekundę.   • Blokady. Gdy w karcie Model jest włączona opcja „Model wymaga blokady do edycji”, asystent blokuje obiekt na swoje konto na czas zapisu i po zapisie blokadę zdejmuje. Obiektu zablokowanego przez innego użytkownika nie zmieni; komunikat podaje, kto blokuje element (konto lub grupa, od kiedy), jego pakiet i diagram.

  • Sprawdzaj wynik. Asystent może się pomylić: źle odczytać zdjęcie, wybrać inny typ elementu albo ułożyć diagram nieczytelnie. Poproś o pokazanie diagramu po zmianach i o poprawki.
  • Duże diagramy asystent zapisuje w kilku krokach. To normalne.

Publikacja strony w Confluence też zawsze pyta i mówi wprost, gdy zastąpi istniejącą stronę (rozdział 13).

Wskazówka: podawaj klucz zgłoszenia i nazwę pakietu. Gdy nie wskażesz projektu, nowe zgłoszenie powstaje w projekcie domyślnym z karty Jira.

8.12 Praca zespołowa (Compass Hub)

Z hubem zespołu (rozdział 22; karta Zespół (Compass Hub) w Ustawieniach) zmianę w modelu możesz najpierw zaproponować zespołowi: asystent niczego nie zapisuje w modelu, tylko wysyła do huba zestaw zmian z opisem i podglądem „przed → po”. Zespół komentuje go w widoku webowym, a architekt albo administrator zatwierdza lub odrzuca. Nikt, nawet administrator, nie może zatwierdzić własnego zestawu zmian. Zatwierdzony zestaw wprowadzasz w Compassie.

Zaproponuj zespołowi zmianę do przeglądu: dodaj klasę Warehouse do pakietu Shop domain.
Pokaż zatwierdzone zestawy zmian i wprowadź CH-…

Co zobaczysz: po propozycji komunikat „Zestaw zmian dla zespołu: …” z numerem (CH-…), a w widoku webowym huba nowy wiersz w zakładce Change sets. Przy wprowadzaniu: zwykły panel zatwierdzania i sprawdzenie po zapisie; hub oznacza zestaw jako wprowadzony. Wprowadzić można tylko zestaw zatwierdzony i dotyczący tego modelu, i tylko raz: Compass najpierw rezerwuje go w hubie, a po zapisie zgłasza wynik.

Widok webowy. Osoby bez Enterprise Architect logują się w nim nazwą użytkownika i hasłem od administratora huba (adres https://<hub>/; http:// tylko na tym samym komputerze). Zakładki mają angielskie nazwy: Ask (pytania do modelu), Search (wyszukiwanie elementów), Model check (kontrola modelu według reguł zespołu), Gaps (luki as-is / to-be), Audit trail (zespołowy dziennik zmian), Team notes (wspólne notatki) i Change sets (propozycje zmian z komentarzami i decyzją). W zakładce Ask wpisujesz pytanie własnymi słowami, na przykład „Które systemy korzystają z bramki płatności?”. Asystent w tym miejscu tylko czyta model: nie ma dostępu do plików, Jiry, Confluence ani serwerów MCP i nie może niczego zaproponować ani zapisać. Odpowiada na jedno pytanie naraz (pytanie ma najwyżej 2000 znaków), a pytania trafiają do dziennika huba.

Wskazówka: nadaj propozycji tytuł, z którego recenzent pozna zakres zmiany bez otwierania szczegółów. Zestaw zmian jest przypisany do modelu: wprowadzisz go tylko w Compassie połączonym z tym samym modelem huba.

8.13 Dodatkowe narzędzia z serwerów MCP

Serwery wpisujesz w pliku mcp_servers.json (rozdział 7) albo dodajesz gotowe (Azure DevOps, GitHub, ServiceNow / CMDB, Files, Compass Hub) i sprawdzasz w Ustawieniach, w karcie Serwery MCP, przyciskiem Zapisz i sprawdź serwery MCP.

Co zobaczysz: w karcie kroków wywołanie narzędzia serwera, a potem jego wynik w odpowiedzi. Każde wywołanie narzędzia pyta o Twoją zgodę, chyba że serwer ma "trusted": true; ustawiaj to tylko dla serwerów, którym ufasz.

Wskazówka: w poleceniu podaj nazwę serwera z pliku mcp_servers.json („przez serwer MCP hub…”), żeby asystent wiedział, którego użyć. Tokeny trzymaj w Menedżerze poświadczeń Windows pod ich własnymi nazwami (${secret:nazwa}), nie w pliku; własnych kluczy i haseł Compassa nie można tam użyć (rozdział 7).

8.14 Compass w Enterprise Architect

Gdy Compass jest zadokowany w EA (rozdział 10), pilnuje modelu w trakcie Twojej pracy i nie wymaga żadnego polecenia. Wyniki trafiają do zakładki Loonar Compass okna System Output:

  • Kontrola na bieżąco: po narysowaniu relacji i po edycji elementu (nazwy, stereotypu, tagged values) pojawia się „⚠ Kontrola modelu: …”, według tych samych reguł co w podrozdziale 8.4.
  • Pisownia: notatki zmienionego elementu są sprawdzane w języku Compassa i dają „✎ Pisownia: …”.
  • Agenci zdarzeń: własne reguły w pliku event_agents.json (karta Agenci zdarzeń (Compass w EA)) uruchamiają asystenta po zdarzeniu w EA. Jego uwagi zaczynają się od 🤖.

Przykładowa reguła, która po utworzeniu komponentu sprawdza właściciela i opis:

{"agents":[{"name":"Component owner","event":"element_created","applies_to":"Component",
  "prompt":"Check that the new component has an owner and a description; suggest what to fill in."}]}

Co zobaczysz: w System Output linię w rodzaju „🤖 Component owner: …” z uwagami asystenta. Agent tylko czyta model: nie ma dostępu do plików, Jiry, Confluence ani serwerów MCP i nie może niczego zaproponować ani zapisać. Ten sam agent reaguje na ten sam obiekt najwyżej raz na minutę. Nowy element jest sprawdzany dopiero po pierwszej edycji, bo EA nadaje mu najpierw nazwę Class1.

Wskazówka: pisz krótkie, konkretne polecenia agentów i zawężaj je przez applies_to (typ, «stereotyp» albo *). Po zmianie pliku kliknij Zapisz agentów zdarzeń. Agent może też pilnować usuwania i je zatrzymywać (punkt 8.22).

8.15 Sprawdzanie modelu w potoku CI

Tryb sprawdzania wykonuje kontrolę modelu, porównanie z kodem i z CMDB oraz łańcuch wymagań bez okna i bez modelu AI, a kończy się kodem wyjścia, który rozumie potok (rozdział 23).

LoonarCompass.exe --check --model model\shop.qea --rules governance.json --code src --requirements docs\wymagania.md --junit junit.xml --fail-on error --lang pl | Out-Host

Co zobaczysz: raport Markdown na standardowym wyjściu, który zaczyna się od wyniku, PASSED albo FAILED, a dalej ma sekcje kontroli modelu, modelu a kodu i wymagań. W potoku plik JUnit pokazuje każdą grupę ustaleń jako test, nieudany, gdy jej waga jest na progu --fail-on albo wyżej. Kod wyjścia to 0, gdy sprawdzenie przeszło, 1, gdy są takie ustalenia, i 2 przy błędnych argumentach albo modelu, którego nie da się odczytać.

Wskazówka: zacznij od --fail-on error i trzymaj ostrzeżenia w raporcie; przejdź na warning, gdy model będzie czysty. Trzymaj governance.json w repozytorium i podawaj go opcją --rules, żeby potok i ludzie stosowali te same reguły.

8.16 CMDB a model

Asystent porównuje pozycje konfiguracji z CMDB (eksport albo dane z serwera MCP) z komponentami modelu i pokazuje, czego brakuje po każdej stronie oraz gdzie różni się właściciel albo status (rozdział 7, „CMDB a model”).

Porównaj eksport CMDB C:\Eksport\cmdb_ci_appl.csv z komponentami modelu.
Pobierz z ServiceNow aplikacje (CI) i porównaj je z modelem.

Co zobaczysz: przy pliku, który nie jest załącznikiem rozmowy, najpierw pytanie, czy asystent może go przeczytać; przy serwerze MCP ServiceNow wywołanie jego narzędzia (z pytaniem o zgodę, chyba że serwer jest zaufany). Potem podsumowanie „CMDB ↔ model: pozycje CMDB: …, elementy modelu: …, dopasowane: …” i sekcje W CMDB, brak w modelu, W modelu, brak w CMDB oraz Inny właściciel lub status. Bez Twojej zgody nic nie jest zapisywane.

Wskazówka: trzymaj identyfikator CMDB (sys_id) w tagged value elementów: wtedy pozycje dopasują się także po zmianie nazwy. Zawęź porównanie do pakietu albo wskaż typy elementów, gdy model zawiera więcej niż CMDB.

8.17 Zgłoszenia Jira i strony Confluence z huba

Gdy administrator ustawi integrations w hub.json (rozdział 22), architekci i administratorzy tworzą zgłoszenia Jira i strony Confluence wprost z widoku webowego huba, bez Compassa i bez EA. Hub używa własnego konta technicznego.

  • Search → kliknij element → Create Jira issue: wpisz podsumowanie; zgłoszenie dostaje szczegóły elementu.
  • Change sets → otwórz zestaw zmian → Create Jira issue for this change set: jedno zgłoszenie na zestaw zmian.
  • Wybierz pakiet w drzewie → Model check → Publish this package to Confluence: wpisz tytuł (pusty: nazwa pakietu i modelu).

Co zobaczysz: „Created ARCH-…” z linkiem do zgłoszenia; w zestawie zmian wiersz „Jira: ARCH-…”; przy Confluence „Created:” albo „Updated:” z linkiem do strony. Każda akcja trafia do zakładki Audit trail z Twoją nazwą.

Wskazówka: strona Confluence to tekstowe podsumowanie pakietu (elementy z opisami i relacje, bez diagramów), zastępowane przy każdej publikacji: zmieniaj model, nie stronę. Stronę z diagramami publikuj z Compassa (rozdział 13).

8.18 Instrukcje modelowania zespołu

Przygotuj instrukcje modelowania dla tego repozytorium.

Zapis, a także dopisana zasada z drugiego polecenia, przechodzą przez zwykły panel zgody jako zmiana elementu „Loonar Compass – modelling instructions”.

8.22 Strażnik, który zatrzymuje usunięcie

Agenta zdarzeń z "mode": "guard" EA pyta, zanim coś usunie, a on może usunięcie zatrzymać (rozdział 10, „Agenci zdarzeń”).

{"agents":[{"name":"Zatwierdzone zostają","event":"element_deleting","mode":"guard","applies_to":"Requirement",
  "prompt":"Zablokuj usunięcie wymagania, którego status to Approved."}]}

10. Compass w Enterprise Architect

Loonar Compass działa też wewnątrz Enterprise Architect, jako okno zadokowane obok przeglądarki projektu i diagramów. Pracujesz w nim tak samo jak w osobnej aplikacji: rozmowa, załączniki, zatwierdzanie zmian, pamięć, szablony i dokumenty działają bez zmian. Osobna aplikacja, uruchamiana z menu Start, też działa jak dotąd.

Instalacja i uruchomienie

  1. W instalatorze, na stronie „Folder docelowy”, zaznacz „Dodaj Loonar Compass do Enterprise Architect”. Działa to z każdą instalacją Enterprise Architect, także z wersją próbną. Po instalacji uruchom EA ponownie.
  2. Otwórz projekt w Enterprise Architect: plik albo bazę danych.
  3. Na wstążce Start, w grupie Add-Ins, kliknij Loonar Compass (przycisk znajdziesz też w Specialize). Przycisk działa tylko przy otwartym projekcie.
  4. Compass otwiera się jako okno zadokowane w EA, w tym samym miejscu co okno Properties. Możesz je przeciągnąć w inne miejsce, odpiąć albo dołączyć do grupy zakładek; EA zapamiętuje, gdzie je umieściłeś.

Projekt i rozmowy

  • W EA Compass zawsze pracuje na projekcie otwartym w tym oknie EA: pliku albo dowolnej bazie danych. Czyta model przez sam Enterprise Architect, więc nie potrzebuje ustawień modelu, haseł ani wyboru modelu rozmowy. Otwarcie w EA innego projektu przełącza Compass na ten projekt; bez otwartego projektu Compass nie działa.
  • Rozmowy wybierasz z listy rozwijanej u góry okna. Lista pokazuje tylko rozmowy z tym projektem. Przycisk + zaczyna nową rozmowę, a ołówek zmienia nazwę wybranej.
  • Ikony widoków są na dole okna, a w wąskim oknie strony przewijają się w poziomie i w pionie.
  • Ctrl + V wkleja obrazy, pliki i tekst, tak jak w osobnej aplikacji.
  • Ustawienia w EA nie mają kart Model i Enterprise Architect. Karty Model AI, Język i zatwierdzanie zmian, Confluence, Miro, Jira, SharePoint i Zespół (Compass Hub) działają tak samo jak w osobnej aplikacji (rozdział 5).

Zmiany, diagramy i odwołania do obiektów

  • Zapisy idą przez to samo okno EA, więc zmiany widać od razu w przeglądarce projektu i na diagramach. Zatwierdzanie zmian działa jak w osobnej aplikacji (rozdział 16).
  • Pokaż diagram i Edytuj diagram otwierają diagram w samym EA, zamiast pokazywać obrazek na czacie.
  • Kliknij element, pakiet albo diagram prawym przyciskiem myszy (w przeglądarce projektu albo na diagramie) i wybierz Specialize → Dodaj do rozmowy w Compass. Do wiadomości trafia odwołanie do obiektu, na przykład «Pakiet: Sklep (id 5)», a asystent wie, o który obiekt chodzi. Przycisk ⌖ w karcie wiadomości dodaje takie same odwołania przez wyszukanie w modelu (rozdział 6, „Wybierz z modelu”).
Opisz «Pakiet: Sklep (id 5)» i zaproponuj brakujące wymagania.

Kontrola na bieżąco

Gdy Compass jest zadokowany w EA, sprawdza zmiany w trakcie Twojej pracy według tych samych reguł co kontrola modelu (wbudowanych i z governance.json albo z huba). Kontrola rusza po narysowaniu relacji i po edycji elementu (nazwy, stereotypu, tagged values). Ustalenia pojawiają się w zakładce Loonar Compass okna System Output, każde tylko raz, jako „⚠ Kontrola modelu: …”. Nowy element jest sprawdzany dopiero po pierwszej edycji, bo EA nadaje mu najpierw nazwę Class1.

Agenci zdarzeń

Karta Agenci zdarzeń (Compass w EA) zawiera reguły, według których asystent reaguje na to, co dzieje się w EA. Reguły są w pliku event_agents.json:

{"agents":[{"name":"Component owner","event":"element_created","applies_to":"Component",
  "prompt":"Check that the new component has an owner and a description; suggest what to fill in."}]}
  • Zdarzenia (event), łącznie 18:
    • elementy: element_created, element_changed, element_deleting;
    • połączenia: connector_created, connector_changed, connector_deleting;
    • diagramy: diagram_created, diagram_changed, diagram_deleting;
    • pakiety: package_created, package_changed, package_deleting;
    • atrybuty i metody: attribute_created, attribute_deleting, method_created, method_deleting;
    • słownik projektu: glossary_term_created, glossary_term_deleting.
    W applies_to podajesz typ elementu, «stereotyp» albo * (działają symbole * i ?).
  • Agenci działają, gdy Compass jest otwarty w swojej zakładce w EA. Asystent czyta model i odpowiada w zakładce Loonar Compass okna System Output (linie zaczynają się od 🤖). Tylko czyta model: nie ma dostępu do plików, Jiry, Confluence ani serwerów MCP i nie może niczego zaproponować ani zapisać.
  • Ten sam agent reaguje na ten sam obiekt najwyżej raz na minutę.
  • Przycisk Zapisz agentów zdarzeń zapisuje reguły i podaje liczbę agentów.

Strażnicy. Domyślnie agent doradza po zdarzeniu ("mode": "advise"). Z "mode": "guard", dozwolonym tylko dla zdarzeń *_deleting, EA pyta Compass, zanim usunie obiekt. Strażnik odpowiada ALLOW albo BLOCK z przyczyną. Przy BLOCK EA pokazuje „Loonar Compass zatrzymał to usunięcie:” z przyczyną i anuluje usunięcie. Jeśli strażnik nie zdecyduje w ciągu 40 sekund albo nie może zdecydować, usunięcie zostaje wstrzymane z komunikatem. System Output pokazuje „🛡 …: dozwolone” albo „🛡 …: zablokowane - …”.

{"agents":[{"name":"Zatwierdzone zostają","event":"element_deleting","mode":"guard","applies_to":"Requirement",
  "prompt":"Zablokuj usunięcie wymagania, którego status to Approved."}]}

Agenci zespołu. Z hubem zespołu (rozdział 22) agenci z polityki zespołu (event_agents) działają w Compassie w EA u każdego, obok agentów tego komputera. Ich nazwy mają dopisek „(team)”.

Pisownia na bieżąco. Notatki zmienionego elementu są sprawdzane w języku Compassa; uwagi pojawiają się w System Output jako „✎ Pisownia: …”.

Kroki asystenta w System Output

Okno System Output w EA ma zakładkę Loonar Compass: Twoje wiadomości i każdy krok asystenta (odczyty modelu, zapisy do EA, wyniki, plan „📋 Plan: …” większej pracy) z godziną. Czat w oknie Compass pokazuje w tym czasie tylko ostatni krok, w jednej linii.

Zamykanie. Compass zamyka się razem z Enterprise Architect i zapisuje rozmowę. Po zamknięciu projektu w EA Compass prosi o otwarcie projektu.

11. Edytor diagramów

Każdy diagram z EA pokazany w rozmowie ma przycisk Edytuj diagram. Otwiera on diagram w oknie edytora, w którym zmieniasz go myszą. Edytor działa na modelu, nie na obrazku: to, co zapiszesz, trafia do EA przez te same operacje, których używa asystent, z panelem zatwierdzania i dziennikiem zmian (rozdział 16). Edytor potrzebuje WebView2, który jest częścią Windows 10 i 11. W Compass w EA przycisk Edytuj diagram otwiera diagram w samym Enterprise Architect (rozdział 10).

Rysowanie

  • Przesuwanie, zmiana rozmiaru i wyrównywanie elementów myszą i przyciskami wyrównania; Ctrl+Z i Ctrl+Y cofają i ponawiają.
  • Dodaj: przyciski zależą od rodzaju diagramu (klas, komponentów, przypadków użycia, aktywności, BPMN, maszyny stanów, wdrożenia, pakietów, sekwencji). Nowy element trafia w wolne miejsce blisko środka widoku; od razu wpisz jego nazwę.
  • Łączenie: przeciągnij od jednego elementu do drugiego. Rodzaj relacji wybierasz na liście Połączenie.
  • Z modelu… wstawia na diagram element, który już jest w modelu (wyszukiwanie po nazwie, typie lub pakiecie). Jego relacje z elementami diagramu pojawią się po zapisie.
  • Dwuklik na elemencie lub relacji zmienia nazwę.

Właściwości

Panel Właściwości pokazuje zaznaczony element lub relację. Każde pole ma znaczek model (zmiana obowiązuje wszędzie, gdzie obiekt jest pokazany) albo diagram (tylko ten diagram).

  • Ogólne: nazwa, alias, stereotyp, słowa kluczowe, status, wersja, autor, faza, złożoność, abstrakcyjny i notatki; pakiet, GUID i daty tylko do odczytu. Dla relacji: nazwa, stereotyp, kierunek, krotności i role obu końców, notatki.
  • Atrybuty i operacje (klasy, interfejsy, komponenty): dodawanie, zmiana (widoczność, nazwa, typ) i usuwanie; nowa operacja przyjmuje parametry w postaci nazwa: Typ, inna: Typ.
  • Tagi: zmiana, dodawanie i usuwanie; gdy profil podaje dozwolone wartości (na przykład typy zadań BPMN), wybierasz z listy.
  • Wygląd: kolor wypełnienia na tym diagramie albo domyślny kolor elementu oraz styl linii relacji na tym diagramie.

Usuwanie

Klawisz Delete usuwa bez pytania to, co dodałeś w edytorze. Przy obiekcie, który już jest w modelu, edytor pyta: Usuń z tego diagramu (zostaje w modelu i na innych diagramach) albo Usuń z modelu (trwale, razem z relacjami, ze wszystkich diagramów). Pokazuje, na jakich innych diagramach jest element i ile ma relacji.

Diagramy sekwencji

Linie życia mają nagłówek i przerywaną linię; przesuwają się tylko w poziomie. Komunikaty idą od góry w swojej kolejności, z numerami, tak jak rysuje je EA. Kolejność zaznaczonego komunikatu zmieniasz przyciskami ▲ ▼ w panelu albo Alt+↑ / Alt+↓. Nowy komunikat (przeciągnij od jednej linii życia do drugiej) trafia zaraz po zaznaczonym. W panelu ustawiasz rodzaj (synchroniczny albo asynchroniczny), czy to odpowiedź, i możesz nazwać go operacją odbiorcy.

Zapis

  • Zapisz do EA zapisuje zmiany i zamyka edytor; wynik pojawia się w rozmowie. Anuluj zamyka go bez zapisu.
  • Uporządkuj z AI zapisuje zmiany i prosi asystenta w rozmowie o takie rozmieszczenie diagramu, żeby dobrze się czytał, bez dodawania, usuwania i zmiany nazw.

12. Wysyłanie diagramów do Miro

Diagram z EA może trafić na tablicę Miro jako edytowalne kształty i połączenia w ramce z nazwą diagramu. Tylko z EA do Miro: to, co ktoś zmieni na tablicy, nie wraca do modelu.

Konfiguracja, jednorazowo:

  1. W Miro otwórz ustawienia profilu → Your apps → Create new app. Miro najpierw prosi o założenie Developer team (darmowej piaskownicy na Twoje aplikacje): zaakceptuj warunki i utwórz go. W organizacji na planie Enterprise zakłada go administrator organizacji.
  2. Nadaj aplikacji nazwę (na przykład Loonar Compass) i nie zaznaczaj „Expire user authorization token”: wygasający token przestaje działać po godzinie.
  3. W sekcji Permissions zaznacz boards:read i boards:write.
  4. Kliknij Install app and get OAuth token i wybierz organizację oraz zespół, których tablic aplikacja może używać (na pierwszy test: Developer team). Skopiuj token.
  5. Wklej go w Ustawieniach, karta „Miro”, i kliknij Zapisz i sprawdź połączenie z Miro. Token jest przechowywany w Menedżerze poświadczeń Windows.

Diagramy trafiają tylko na tablice zespołu, w którym aplikacja jest zainstalowana; żeby wysyłać do innej organizacji, zainstaluj aplikację także tam (tym samym przyciskiem).

Wysyłanie:

  1. Kliknij Wyślij do Miro pod diagramem w rozmowie.
  2. Wybierz tablicę (pierwsza jest ta użyta ostatnio; pole wyszukiwania filtruje po nazwie).
  3. Miniatura pokazuje, co już jest na tablicy (szare), i gdzie trafi diagram (niebieska ramka, czerwona, gdy coś by zasłoniła). Aplikacja sama znajduje wolne miejsce; przeciągnij ramkę, żeby wybrać inne.
  4. Kliknij Wyślij do Miro. Po wysłaniu w rozmowie pojawia się wiadomość z linkiem, który otwiera tablicę na nowej ramce.

Diagramy sekwencji trafiają jako linie życia z ponumerowanymi komunikatami w kolejności z EA (odpowiedzi przerywaną linią). Ponowne wysłanie tego samego diagramu stawia nową ramkę obok poprzedniej, więc nic, co zmieniono na tablicy, nie zostaje nadpisane.

17. Rozmowy: historia, wyszukiwanie, praca w tle

  • Nowa rozmowa: przycisk + nad listą rozmów. Każda rozmowa jest zapisywana i wraca po ponownym uruchomieniu aplikacji.
  • Grupy: rozmowy są pogrupowane na „Dzisiaj”, „Wczoraj”, „Ostatnie 7 dni” i „Wcześniej”.
  • Wyszukiwanie: pole „Szukaj w rozmowach…” filtruje listę po tytule i po treści wiadomości.
  • Zmiana nazwy: kliknij ołówek przy wybranej rozmowie, wpisz nazwę, Enter zapisuje, Esc anuluje.
  • Kilka rozmów naraz: w trakcie pracy asystenta możesz zacząć nową rozmowę albo przejść do innej. Rozpoczęta praca toczy się w tle.
  • Usuwanie: kliknij rozmowę na liście prawym przyciskiem myszy i wybierz Usuń rozmowę. Jej plik trafia do folderu history\bin (rozdział 18), więc rozmowę przywrócisz, przenosząc plik z powrotem do history, gdy aplikacja jest zamknięta. Rozmowy, w której asystent pracuje, nie da się usunąć, dopóki nie skończy.
  • Długie rozmowy: gdy rozmowa przekroczy około 100 000 tokenów, jej wcześniejsza część jest na potrzeby kolejnych odpowiedzi zastępowana streszczeniem napisanym przez model, a najnowsze wiadomości zostają słowo w słowo. Pokazuje to krok „Rozmowa jest długa: streszczam jej wcześniejszą część”. Dzięki temu odpowiedzi są szybkie, a rozmowa nigdy nie dochodzi do limitu modelu; historia, którą widzisz na czacie, zostaje pełna.
  • Model rozmowy: każda rozmowa pracuje z własnym modelem EA, a nowa rozmowa zaczyna się od zatwierdzenia tego modelu. Ekran nowej rozmowy pokazuje model domyślny z ustawień. Przycisk Wybierz inny model… otwiera okno „Model tej rozmowy”, w którym wybierasz Domyślny z ustawień albo Inny model: Baza PostgreSQL (serwer, port, nazwa bazy, użytkownik, hasło, szyfrowanie połączenia) albo Plik EA (.qea, .qeax), z kontem EA i opcjami zabezpieczeń jak w karcie Model. Sprawdź połączenie otwiera model, liczy pakiety, elementy i diagramy oraz zapisuje w nim pakiet próbny, który sprawdza i od razu usuwa. Przycisk Zatwierdź model i rozpocznij ustala model rozmowy: potem nie można go już zmienić, a przycisk Model: … w nagłówku pokazuje go tylko do podglądu. Aby pracować na innym modelu, zacznij nową rozmowę. Zmiana modelu domyślnego w ustawieniach nie zmienia trwających rozmów. Hasła połączenia innego niż w ustawieniach trafiają do Menedżera poświadczeń Windows. W Compass w EA modelem rozmowy jest zawsze projekt otwarty w EA (rozdział 10).
  • Plik EA upuszczony na okno: plik .qea lub .qeax upuszczony na czat staje się modelem rozmowy, a nie załącznikiem. Jeśli rozmowa ma już wiadomości, z tym plikiem zaczyna się nowa rozmowa.
  • Rozmowy z wcześniejszych wersji przy pierwszym uruchomieniu wersji 0.5 lub nowszej dostają kopię modelu z ustawień, więc pracują z nim dalej, nawet gdy później zmienisz ustawienia. Po najechaniu myszą na rozmowę na liście widać jej model.

Co trafia do dostawcy modelu AI

Żeby asystent mógł odpowiadać, w każdym zapytaniu do wybranego dostawcy modelu AI (Anthropic albo OpenAI, karta Model AI) aplikacja wysyła: treść rozmowy, załączone pliki, pełną treść pamięci asystenta, instrukcje modelowania repozytorium, listę szablonów z opisami oraz to, co asystent odczytał z modelu w danej rozmowie, czyli wyniki jego zapytań do bazy (na przykład nazwy i opisy pakietów, elementów i diagramów) i obrazki diagramów. Nie jest wysyłana cała baza, tylko to, o co asystent zapytał. Treść szablonu trafia do modelu, gdy asystent go użyje, a po zmianie języka trafiają też pamięć i szablony do przetłumaczenia.

Dane trafiają bezpośrednio do wybranego dostawcy (api.anthropic.com albo api.openai.com) z użyciem Twojego klucza API; drugi dostawca nie dostaje niczego. Loonar ich nie otrzymuje, a aplikacja nie zbiera żadnych danych o korzystaniu (brak telemetrii). Z claude.url (rozdział 5) zapytania idą zamiast tego pod ten adres, na przykład do Twojego zasobu Azure AI Foundry albo firmowej bramki.

Uprawnienia asystenta

  • Bazę asystent czyta w sesji tylko do odczytu, a plik modelu otwiera tylko do odczytu: wyłącznie zapytaniami SELECT i WITH, z limitem czasu zapytania i bez funkcji serwera, które czytają pliki albo wpływają na inne sesje. Wszystkie zmiany idą przez Enterprise Architect, na koncie EA modelu (z karty Model albo z modelu rozmowy), więc obowiązują je uprawnienia i blokady tego konta. Compass w EA czyta i zapisuje model przez okno EA, w którym jest otwarty, na koncie, na którym zalogowałeś się w EA.
  • Ochrona przed ukrytymi instrukcjami (prompt injection). Dokument, zgłoszenie, strona albo notatka w modelu mogą zawierać tekst napisany po to, żeby sterować asystentem. Asystent dostaje zasady bezpieczeństwa w każdym zapytaniu; wyniki z dokumentów, Jiry, Confluence, serwerów MCP, CMDB i kodu są oznaczone jako dane, a nie polecenia; a odpowiedź, która powtarza słowo w słowo wewnętrzne instrukcje asystenta, jest wstrzymywana („Odpowiedź powtarzała wewnętrzne instrukcje asystenta i została wstrzymana.”). Asystent nie wykonuje znalezionych tam instrukcji i nie wysyła danych w miejsca, które ta treść wskazuje, a zapisy nadal wymagają Twojej zgody (rozdział 16).
  • W Confluence asystent działa z uprawnieniami tokena z karty „Confluence” i publikuje tylko po Twoim zatwierdzeniu.
  • Asystent nie ma dostępu do plików na dysku poza tymi, które sam mu załączysz, oraz poza swoimi folderami pamięci i szablonów; każdy inny plik (dokument wymagań, folder z kodem) czyta dopiero po zapytaniu Cię o zgodę. Obrazki rysowane przez asystenta nie mogą wczytać plików z dysku ani z sieci.
  • Login i hasło z ciągu połączenia otwartego okna EA nigdy nie trafiają do modelu językowego.

Połączenia i szyfrowanie

  • API modelu AI (Anthropic albo OpenAI albo adres z claude.url), Confluence, Jira, SharePoint, Miro i adresy tokenów OAuth2: wyłącznie HTTPS (http:// jest dopuszczalny tylko dla serwera na tym samym komputerze).
  • Baza modelu: połączenie może być szyfrowane TLS, zależnie od ustawienia w karcie Model (rozdział 5). Administrator bazy może wymusić TLS dla wszystkich klientów wpisami hostssl w pg_hba.conf. Połączenie samego Enterprise Architect z bazą zależy od ustawień EA.
  • Proxy: aplikacja korzysta z proxy z ustawień internetowych Windows oraz ze zmiennych środowiskowych HTTPS_PROXY i ALL_PROXY. Skrypty PAC i uwierzytelnianie NTLM/Kerberos na proxy nie są obsługiwane.
  • Chwilowe błędy API modelu AI (przeciążenie 529 i inne błędy 5xx, limit zapytań 429) aplikacja ponawia automatycznie.

Instalacja huba

Hub to osobny program, compass-hub, dla Windows i Linuksa. Czyta modele wprost (baza PostgreSQL, SQL Server, MySQL/MariaDB albo Oracle albo pliki .qea/.qeax), więc na serwerze nie jest potrzebny Enterprise Architect. Do pobrania:

  • Windows: CompassHub-0.9.0-windows-x64.zip z plikiem compass-hub.exe, przykładowym hub.json i plikiem README.
  • Docker: obraz ghcr.io/loonar-eu/compass-hub:0.9.0 albo własna kompilacja w głównym folderze repozytorium: docker build -f hub/Dockerfile -t compass-hub .

W konsoli (Windows albo Linux). Hub działa, dopóki nie zamkniesz konsoli:

Jako usługa Windows, w konsoli uruchomionej jako administrator. Usługa „CompassHub” startuje od razu i razem z Windows; zatrzymujesz ją w Usługach albo poleceniem sc stop CompassHub, a usuwasz opcją --service-uninstall:

docker run -d --name compass-hub -p 8730:8730 -v /srv/compass-hub:/data \
  -e LOONAR_SECRET_CLAUDE_API_KEY=... ghcr.io/loonar-eu/compass-hub:0.9.0

Konta i logowanie

Do widoku webowego (https://<hub>/; http:// tylko na tym samym komputerze) ludzie logują się nazwą użytkownika i hasłem. Compass i klienci MCP używają tokenu API.

Konto domyślne. Nowy hub (hub.json bez użytkowników) tworzy konto admin z hasłem passw0rd (z zerem). Przy pierwszym logowaniu hub prosi o zmianę hasła i do tego czasu nie pozwala na nic innego. Zrób to, zanim hub będzie dostępny z innych komputerów.
  • Hasło ma co najmniej 10 znaków i nie może być hasłem domyślnym ani nazwą użytkownika. Hub przechowuje hasła tylko jako skróty PBKDF2.
  • Zalogowanie trwa 12 godzin; Sign out kończy je od razu.
  • Po 20 błędnych hasłach albo tokenach z jednego adresu ten adres jest odrzucany przez 10 minut.
  • Link Sign in with a token instead na stronie logowania pozwala zalogować się tokenem API.

Zakładka Users (tylko dla administratorów):

  • Add a user (dodaj użytkownika): nazwa, rola i pierwsze hasło, które użytkownik musi zmienić przy pierwszym logowaniu.
  • Role: zmienia rolę (viewer, architect albo admin).
  • Reset password: ustawia nowe hasło, które użytkownik musi zmienić przy następnym logowaniu.
  • New API token: token dla Compassa (Ustawienia → Zespół (Compass Hub)) i dla klientów MCP. Jest pokazywany tylko raz, a poprzedni token użytkownika przestaje działać.
  • Remove: usuwa użytkownika. Hub zawsze zachowuje co najmniej jednego administratora, a siebie usunąć nie możesz.

Zmiana albo usunięcie użytkownika kończy jego zalogowania. Każda zmiana użytkowników trafia do dziennika zmian.

Logowanie kontem firmowym (OpenID Connect)

Ludzie mogą logować się do widoku webowego kontem firmowym: AD FS, Microsoft Entra ID, Keycloak, Okta i inni dostawcy OpenID Connect. Strona logowania pokazuje wtedy przycisk Sign in with your company account. Dopisz do hub.json:

"oidc": {
  "issuer": "https://adfs.example.com/adfs",
  "client_id": "<identyfikator klienta od dostawcy>",
  "redirect_uri": "https://hub.example.com/auth/callback",
  "groups_claim": "groups",
  "roles": { "admin": ["Compass-Admins"], "architect": ["Compass-Architects"], "viewer": ["Compass-Viewers"] },
  "password_login": true
}
  • U dostawcy: zarejestruj hub jako poufną aplikację webową z przepływem authorization code, z powyższym adresem przekierowania (adres huba z /auth/callback), zakresami openid profile email (AD FS: allatclaims hub dodaje sam; zmienia je klucz scopes) i oświadczeniem groups z nazwami grup w tokenie ID. Klucz tajny klienta to sekret huba OIDC_CLIENT_SECRET (LOONAR_SECRET_OIDC_CLIENT_SECRET).
  • Kontrole: logowanie korzysta z PKCE i jednorazowego parametru state; hub sam sprawdza token ID: podpis RS256 kluczami dostawcy, wystawcę, odbiorcę, ważność i nonce.
  • Role z grup: roles podaje grupy, które dają każdą rolę (domyślnie Compass-Admins, Compass-Architects i Compass-Viewers); groups_claim wskazuje oświadczenie z grupami (domyślnie groups). Rola jest ustalana od nowa przy każdym logowaniu, a wygrywa najwyższa. Osoba spoza wszystkich grup nie dostaje dostępu.
  • Nazwa użytkownika: name_claim wybiera oświadczenie (domyślnie upn, potem preferred_username, email). Jeśli lokalny użytkownik huba ma tę samą nazwę, logowanie kontem firmowym jest odrzucane, dopóki administrator nie zmieni nazwy tego użytkownika albo go nie usunie.
  • Tylko logowanie firmowe: "password_login": false wyłącza logowanie nazwą i hasłem. Tokeny API dla Compassa i klientów MCP działają dalej. button zmienia tekst przycisku.
  • Każde logowanie kontem firmowym trafia do dziennika zmian.

Bezpieczeństwo huba

Hub komunikuje się zwykłym HTTP. Do dostępu z innych komputerów postaw go za reverse proxy z HTTPS (na przykład IIS albo nginx) i podawaj ludziom adres https://. Od razu zmień hasło konta domyślnego. Chroń plik hub.json i folder danych uprawnieniami do plików. Zapytania mają ograniczony rozmiar i czas. Po 20 błędnych hasłach albo tokenach z jednego adresu ten adres jest odrzucany przez 10 minut; poprawny token nadal działa. Błędy wewnętrzne są pokazywane tylko jako identyfikator, a szczegóły są w hub.log. Widok webowy trzyma zalogowanie tylko na czas sesji przeglądarki i ma przycisk Sign out (wyloguj).

IIS z ARR przed hubem: hub nasłuchuje tylko na tym komputerze ("listen": "127.0.0.1:8730"), a witryna IIS z certyfikatem przekazuje ruch na http://127.0.0.1:8730/ (URL Rewrite + Application Request Routing). W ustawieniach proxy ARR wyłącz przepisywanie nagłówków odpowiedzi: reverseRewriteHostInResponseHeaders="false" (Menedżer IIS → serwer → Application Request Routing Cache → Server Proxy Settings → odznacz „Reverse rewrite host in response headers”). Inaczej ARR podmienia adres przekierowania do AD FS lub Entra ID na adres huba i logowanie firmowe się nie udaje. Nagłówek Authorization musi przechodzić bez zmian (domyślnie przechodzi). Hub ufa nagłówkowi X-Forwarded-For tylko od proxy na tym samym komputerze: blokada po błędnych hasłach dotyczy wtedy adresu klienta, a nie wszystkich naraz. Nieudane i odrzucone logowania (hasłem i kontem firmowym) są w zakładce Audit trail z wynikiem ✗ i adresem klienta, a zakładka Users pokazuje też konta firmowe z rolą i czasem ostatniego logowania (tylko do odczytu: rolę zmienia się w grupach u dostawcy).

Serwer MCP

Serwer MCP (tylko odczyt) działa jako JSON-RPC przez HTTP POST pod adresem /mcp, z nagłówkiem Authorization: Bearer <token>. Narzędzia: list_sources, list_packages, search_elements, element_details, impact_analysis, model_lint, gap_analysis.

GraphQL i tabele dla Power BI

Inne narzędzia czytają modele huba z tokenem API (zakładka Users, nagłówek Authorization: Bearer <token>); czytać może każda rola, a niczego nie da się zmienić.

  • GraphQL: POST /api/sources/{sourceId}/graphql z {"query": "…"}. Zapytania: packages, package, elements(name, type, stereotype, package, limit), element, diagrams, diagram. Elementy mają attributes, operations, taggedValues, connectors (z source i target) oraz package. Schemat w SDL jest pod GET /api/graphql/schema.
  • Tabele: GET /api/sources/{sourceId}/table/{table} zwraca płaską tabelę jako JSON, dla elements, connectors, packages, diagrams, attributes albo tagged_values.
  • Power BI: Pobierz dane (Get Data) → Sieć Web (Web) → Zaawansowane (Advanced); adres tabeli, a w nagłówkach żądania HTTP Authorization z wartością Bearer <token API>. Excel i inne narzędzia działają tak samo.

Klucze AI, Jira i Confluence na hubie

Hub może trzymać klucze Claude i konta Jira oraz Confluence zespołu, tak żeby ludzie nie mieli ich na swoich komputerach. Klucze są sekretami huba (zmienne LOONAR_SECRET_<NAZWA> albo pliki LOONAR_SECRET_<NAZWA>_FILE), a w hub.json wskazuje się, kto którego używa:

"ai": {
  "keys": [
    {"for": "anna.architekt@lab.local", "secret": "claude_key_anna"},
    {"for": "role:architect", "secret": "claude_key_team"},
    {"for": "*", "secret": "claude_key_team"}
  ],
  "limits": [
    {"for": "role:viewer", "tokens_per_day": 50000},
    {"for": "*", "tokens_per_day": 300000, "tokens_per_month": 5000000}
  ],
  "models": ["claude-haiku-5-5", "claude-sonnet-5-5"]
},
"policy": {"ai_via_hub": true, "jira_via_hub": true, "confluence_via_hub": true, "web_access": false}
  • keys – klucz dla osoby (nazwa z huba albo UPN konta firmowego), dla roli (role:viewer, role:architect, role:admin) albo dla wszystkich (*); wygrywa pierwszy pasujący wpis dla osoby, potem dla roli, potem *. Kto nie ma klucza, dostaje odmowę.
  • limits – tokeny (wejście + wyjście) na dzień i na miesiąc, w tej samej kolejności. Zużycie każdej osoby widać w zakładce Users (dziś i w tym miesiącu); szczegóły są w ai_usage.jsonl.
  • models – opcjonalnie: tylko te modele.
  • Polityka: "ai_via_hub": true – Compass pyta Claude przez hub (bez własnego klucza); "jira_via_hub" i "confluence_via_hub" – Compass korzysta z Jiry i Confluence przez hub, kontem z sekcji integrations (viewer tylko czyta, każda zmiana trafia do audytu z nazwą osoby), a projekt i przestrzeń zespołu są domyślne.

Zasady komputera: wymuszenie huba (GPO, Intune)

Polityka zespołu w hubie działa u tych, którzy są do niego podłączeni. Żeby obowiązywała wszystkich, dział IT ustawia zasady komputera w kluczu HKLM\SOFTWARE\Policies\Loonar\Compass (dla komputera) albo HKCU\SOFTWARE\Policies\Loonar\Compass (dla użytkownika), przez zasady grupy (GPO) albo Intune. Zwykły użytkownik nie może ich zmienić. Zasady tylko zaostrzają ustawienia:

  • HubUrl – adres huba zespołu; pole w ustawieniach jest zablokowane.
  • RequireHub = 1 – asystent działa tylko po zalogowaniu do huba i z jego polityką. Gdy hub chwilowo nie odpowiada, Compass używa ostatniej otrzymanej polityki (najwyżej sprzed tygodnia); bez niej asystent nie działa.
  • WebAccess = 0 – bez internetu (przycisk 🌐 zablokowany).
  • UpdateCheck = 0 – bez codziennego sprawdzania nowej wersji.
  • MinApproval = ask, plan albo auto – najmniej surowy tryb zatwierdzania.
  • AllowedProviders – dozwoleni dostawcy AI, np. anthropic albo anthropic,openai.

Logowanie kontem firmowym: w Ustawienia → Zespół (Compass Hub) przycisk Zaloguj się kontem firmowym otwiera logowanie huba w przeglądarce (AD FS, Entra ID, Keycloak…); po zalogowaniu hub oddaje sesję jednorazowym adresem na tym komputerze (127.0.0.1) i Compass zapisuje ją w Menedżerze poświadczeń zamiast tokenu. Sesja trwa 12 godzin; potem wystarczy zalogować się ponownie. Szablony zasad grupy (LoonarCompass.admx i pliki językowe .adml) są w folderze deploy\policies repozytorium: skopiuj je do C:\Windows\PolicyDefinitions albo do magazynu centralnego domeny. Kto ma na komputerze uprawnienia administratora, może zasady obejść, tak jak w każdej aplikacji.

23. Tryb sprawdzania w potokach CI

Z opcją --check Loonar Compass sprawdza model bez okna i bez modelu AI, na przykład w potoku CI po każdej zmianie modelu albo kodu. Sprawdzenia wykonuje program, więc ten sam model zawsze daje ten sam wynik, a w modelu nic nie jest zapisywane.

LoonarCompass.exe --check --model <plik.qea|app.properties>
  [--package <id|nazwa>] [--rules governance.json] [--code <folder>]
  [--requirements <dokument>] [--cmdb <eksport.csv|json>] [--report raport.md]
  [--junit junit.xml] [--fail-on error|warning|info|never] [--lang en|pl|de|fr]
OpcjaZnaczenie
--modelPlik EA .qea albo .qeax, czytany wprost i tylko do odczytu (Enterprise Architect nie jest potrzebny), albo plik app.properties instalacji Compassa, na przykład z modelem w PostgreSQL, SQL Server, MySQL albo Oracle. Bez tej opcji: ustawienia użytkownika Windows, który uruchamia polecenie.
--packageSprawdzany pakiet (id albo nazwa), razem z podpakietami. Bez tej opcji: wszystkie pakiety główne modelu.
--rulesPlik governance.json z regułami zespołu (rozdział 7). Bez tej opcji: governance.json obok podanego app.properties albo polityka jego huba; dla pliku modelu tylko reguły wbudowane.
--codeFolder z kodem: model jest porównywany z kodem (podrozdział 8.6), a z --requirements każde wymaganie jest też prowadzone do kodu i testów (rozdział 7, „Łańcuch wymagań”).
--requirementsDokument wymagań: .docx, .pdf, .pptx, .vsdx, .xlsx, .md, .txt albo .html (podrozdział 8.5).
--cmdbEksport z CMDB, CSV albo JSON (rozdział 7, „CMDB a model”).
--reportZapisuje raport Markdown także do tego pliku.
--junitZapisuje plik JUnit XML dla potoku.
--fail-onNajniższa waga, przy której sprawdzenie się nie udaje: error (domyślnie), warning, info albo never.
--langJęzyk raportu: en (domyślnie), pl, de albo fr.

Co jest sprawdzane

CzęśćKiedyWaga
Kontrola modelu: kontrole wbudowane, relacje ArchiMate 3.2, reguły zespołuzawszejak w kontroli modelu (rozdział 7): błąd, ostrzeżenie albo informacja
Model a kod--coderóżnice: ostrzeżenie

Wymagania--requirementswymaganie, którego nie ma w modelu, które ma tylko kandydatów (bez relacji śledzenia) albo ma zgodny identyfikator, ale inną treść: ostrzeżenie; z --code wymaganie bez kodu albo bez testów: informacja

Wynik

  • Raport: Markdown na standardowym wyjściu. Zaczyna się od wyniku, PASSED albo FAILED, i liczby grup błędów i ostrzeżeń, a dalej ma sekcję dla każdej części.
  • JUnit: zestaw testów (test suite) dla każdej części i przypadek testowy dla każdej grupy ustaleń. Grupy z wagą na progu --fail-on albo wyżej są niepowodzeniami, więc potok pokazuje je jako nieudane testy.
  • Kod wyjścia: 0 sprawdzenie przeszło; 1 ustalenia na progu --fail-on albo wyżej; 2 błędne argumenty, model, którego nie da się odczytać, albo plik, którego nie da się zapisać (przyczyna trafia na wyjście błędów).
Program okienkowy w PowerShell. LoonarCompass.exe jest programem okienkowym, więc PowerShell na niego nie czeka. Przekaż jego wyjście dalej, na przykład … | Out-Host: PowerShell wtedy czeka, pokazuje raport i ustawia $LASTEXITCODE. Hasło do bazy z modelem pochodzi ze zmiennej środowiska LOONAR_DB_PASSWORD (zmiennej tajnej potoku) i ma pierwszeństwo przed Menedżerem poświadczeń.

GitLab CI

Zadanie na runnerze Windows (PowerShell) z Loonar Compass zainstalowanym dla wszystkich użytkowników. Zadanie uruchamia sprawdzenie i publikuje junit.xml jako raport testów:

compass-check:
  tags: [windows]
  script:
    - '& "C:\Program Files\Loonar Compass\LoonarCompass.exe" --check --model model\shop.qea --rules governance.json --code src --junit junit.xml --report report.md | Out-Host'
    - 'if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }'
  artifacts:
    when: always
    paths: [report.md]
    reports:
      junit: junit.xml

GitHub Actions

Zadanie na własnym runnerze Windows (self-hosted) z Loonar Compass zainstalowanym dla wszystkich użytkowników. Zadanie uruchamia sprawdzenie i przesyła junit.xml oraz raport jako artefakt, który wybrany krok raportu JUnit może pokazać jako wyniki testów:

jobs:
  compass-check:
    runs-on: [self-hosted, windows]
    steps:
      - uses: actions/checkout@v4
      - name: Model check
        shell: pwsh
        run: |
          & "C:\Program Files\Loonar Compass\LoonarCompass.exe" --check --model model\shop.qea --rules governance.json --code src --junit junit.xml --report report.md | Out-Host
          exit $LASTEXITCODE
      - name: Publish the results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: compass-check
          path: |
            junit.xml
            report.md

Dla modelu w PostgreSQL podaj w --model plik app.properties bez haseł i ustaw LOONAR_DB_PASSWORD: w GitLabie jako maskowaną zmienną CI/CD, w GitHubie z sekretu (env: LOONAR_DB_PASSWORD: ${{ secrets.EA_DB_PASSWORD }}).
