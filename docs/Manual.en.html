1. What Loonar Compass is

Loonar Compass is a standalone Windows desktop application: an AI assistant for working with an Enterprise Architect model (Sparx Systems). You write to it in plain language, and it:

  • reads the model (packages, elements, diagrams, connectors, attributes and operations) and describes what is in it,
  • analyzes the model: the impact of changing an element on the rest of the model, where operations are used, elements without connectors,
  • changes the model: creates packages, diagrams, elements and connectors, adds attributes and operations to classes, sets keywords and tagged values, lays out elements on diagrams, moves them, removes an element from a diagram, deletes objects from the model, colors them, adds legends, copies packages and creates baselines of them,
  • keeps the EA project glossary (terms with their meaning and type) and structured scenarios of elements (actor and system steps),
  • draws diagrams from a description, a photo, a sketch or an attached file,
  • shows diagrams as images in the chat, just as Enterprise Architect draws them,
  • prepares documents from the model's content: Word, Excel, PowerPoint, PDF, PNG images and Confluence pages, also based on templates,
  • reads documents: PDF, Word, PowerPoint, Visio and Excel, from your disk or from the team's SharePoint library,
  • follows the team's modelling instructions kept in the EA repository itself, so everybody who works with the repository uses the same rules,
  • remembers notes between conversations (modeling conventions, preferences, corrections).

The application uses an AI language model over the Internet, with your API key: Claude Haiku 5.5 (Anthropic) by default; in the settings you can choose another Claude model or an OpenAI model (chapter 5). It connects to the EA model in two ways: it reads it directly (from a PostgreSQL, SQL Server, MySQL/MariaDB or Oracle database, or from the .qea/.qeax file) and writes to it through Enterprise Architect, using the model user account given in the settings when the model has one. With a model file you have open in EA, the changes go through your EA window; otherwise EA runs in the background.

The interface and the assistant's answers are available in four languages: Polish, English, German and French (chapter 5). Answers and changes are prepared by an AI model and may contain errors: review them before you approve them (chapter 16).

Loonar Compass runs as a separate window, started from the Start menu, or as a window docked in Enterprise Architect itself, which works with the project open in that EA window (chapter 10).

Without a window, Compass also checks the model in CI pipelines (chapter 23), and the separate program Compass Hub serves the team's models to people and tools (chapter 22).

2. Requirements

Prerequisites. The application works only when the following are met:
  1. The model is an EA project file .qea or .qeax, or is in a PostgreSQL, SQL Server, MySQL/MariaDB or Oracle database. Older file formats (.eap, .eapx, .feap) are not supported; Enterprise Architect converts an .eap/.eapx file to .qea with a project transfer (Settings → Model → Transfer → Full Project Transfer).
  2. A model in a database has user security enabled (in Enterprise Architect: Settings → Security → Enable Security), in “Require User Lock to Edit” mode. In a model file, security is optional: without it, the assistant needs no EA account. The application logs in to the model as a specific user and locks objects while saving. When security is turned off, the locks are skipped; this is not a supported configuration. In the application you mark this on the Model card of the settings with the options “The model has security enabled (EA user accounts)” and “The model requires a lock to edit (Require User Lock to Edit)” (chapter 5).
  3. A model with security enabled has a user account for the assistant (Settings → Security → Users), with a password and edit permissions. The account name can be anything, for example claude or assistant, but the account must exist. You enter its login and password on the Model card of the settings, together with the model file or database.

3. Installation

Run the file LoonarCompass-Setup-0.9.exe. The wizard guides you through the steps with the Next and Back buttons. You do not need administrator rights unless you install the application for all users of the computer.

Windows SmartScreen. The installer is not digitally signed yet, so when you run it for the first time, Windows SmartScreen may show the warning “Windows protected your PC”. Click More info and then Run anyway. If Smart App Control is turned on, Windows blocks unsigned applications altogether; in that case, wait for the signed version.
  1. Language. Polish, English, German or French. For a new installation, English is selected; for an update, the language saved in your settings. The chosen language applies to the wizard, the application, the assistant's answers and the default document templates; you can change it later in the settings (chapter 5).
  2. Welcome. The prerequisites and a list of things worth preparing before installation.
  3. What's new. When updating: the changes since the installed version. For a new installation: the changes in the current version.
  4. License agreement. Select “I accept the terms of the license agreement”.
  5. Destination folder. The installation type (described below), the program folder (Browse…) and the shortcuts: Start menu (application, user guide, uninstall) and Desktop. The option “Add Loonar Compass to Enterprise Architect” installs Compass in EA (chapter 10); restart EA after the installation.
  6. Configuration. Choose “Enter the details now” or “Configure later in the application ("Settings" view)”. The page contains the Claude API key (with a note on what the application sends to Anthropic; you can choose OpenAI later in the settings), the model (a PostgreSQL database: server, port, database name, database user, database password; or an EA file: the path to the .qea/.qeax file, which you can select with the … button), Enterprise Architect (the path to EA.exe, which you can select with the … button, the EA user account and the EA account password) and the approval mode.
  7. Ready to install. A summary of the installation type, folder, shortcuts and configuration. Click Install; the progress bar shows the percentage and the current step.
  8. Installation complete. With “Launch Loonar Compass” selected, the application opens after you click Finish.

Installation type

On the “Destination folder” page, you choose who the application is installed for:

  • “Just for me (recommended, no administrator rights)”: the program is installed in %LOCALAPPDATA%\Programs\Loonar Compass. Windows does not ask for administrator rights.
  • “For all users of this computer (requires administrator rights)”: the program is installed in %ProgramFiles%\Loonar Compass, where only administrators can change files. Only in this case does Windows ask for administrator rights, after you click Install.

Settings, conversations and passwords are always stored for the user who runs the wizard (in %APPDATA%\Loonar Compass and in Windows Credential Manager), also when another person confirms the administrator rights and also in an installation for all users.

Taskbar. Windows 11 does not allow installers to pin programs to the taskbar. Start the application, right-click its icon on the taskbar and choose “Pin to taskbar”.

Updating from an earlier version

Earlier versions of the application were called Loonar EA Assistant: Loonar Compass takes over their settings, conversations, memory, templates and passwords automatically.

  • An earlier version installed just for you is removed during installation (program files, shortcuts and the Windows entry); your data stays.
  • If an earlier version is installed for all users, the “Ready to install” page shows it. You can remove it with the Remove the old version (administrator rights) button, or later in Windows Settings → Apps.
  • On the first page, the wizard preselects the language saved in your settings (settings without a saved language, from versions 0.1 and 0.2, count as Polish), or English when there are no settings. Check this choice before you continue.
  • Changing the language in the wizard does not translate the assistant's memory or your templates. To carry them over to a new language, change the language on the “Language and change approval” card in the settings after installation (chapter 5).
  • A database password that older versions kept in the settings file is moved to Windows Credential Manager, and files with Polish names in the data folder get English names (for example audit_log.jsonl).

Changing the language

The application works in four languages: Polish, English, German and French. You choose the language in the installer (English by default) and change it on the “Language and change approval” card:

  1. Choose a language from the Language list.
  2. Click Save. The interface switches to the new language, and the assistant answers in it from the next message.
  3. The application carries your content over to the new language: it replaces untouched default templates with the versions in the new language, and the assistant's memory and your own and modified templates are translated by the AI model.

Only the memory and the templates are translated. Conversation history is never translated: conversations stay in the language in which you held them.

No connection to the AI model. Translation requires a working API key. If there is no connection, an orange “!” appears on the Settings, Assistant memory and Document templates icons, and the tooltip explains that the content has not been translated yet. The translation resumes the next time the application starts, or immediately when you click the Translate now button on the “Language and change approval” card. Saving other cards does not start it.

When you save the language, Compass also switches EA's own spell checker to that language, if EA has a dictionary for it. EA comes with English dictionaries only, so for other languages Compass checks the texts itself (chapter 7, “Spelling in the language of Compass”).

Database connection encryption

The Connection encryption field on the “Model” card (PostgreSQL database) decides whether the assistant reads the model over TLS:

SettingEffect
Preferred (default)TLS when the server offers it; otherwise an unencrypted connection. Works with any server.
RequiredTLS is required: without it the application does not connect. The server certificate is not verified.
Required, certificate verifiedTLS is required, and the server certificate is verified against the Windows certificate store (including company certificates), together with the server name.
  • The connection test says whether the connection is encrypted: “The connection is encrypted (TLS).” or “The connection is NOT encrypted: the server does not offer TLS.”.
  • With certificate verification, the name in the Server field must match the name in the server certificate.
  • The database administrator can enforce TLS for all clients with hostssl entries in the pg_hba.conf file.
  • The setting applies to the assistant's reading of the model. Enterprise Architect's own connection to the database (when saving) follows EA's settings.
  • With SQL Server, the setting goes to the ODBC driver (“Required”: encrypted, the certificate is not verified; “Required, certificate verified”: encrypted and verified). With MySQL and Oracle, set the encryption in the driver or in db.odbc (below).

SQL Server, MySQL and Oracle

Besides PostgreSQL and EA files, Compass reads EA repositories on SQL Server, MySQL/MariaDB and Oracle: in the separate window, in the team hub (chapter 22) and in check mode (chapter 23). On the Model card choose SQL Server, MySQL or Oracle and fill in the same fields as for PostgreSQL; the port changes to the usual one of that database (1433, 3306, 1521) unless you have changed it yourself. The model of a conversation (chapter 17) can be such a database too.

  • ODBC driver. Compass connects through the 64-bit ODBC driver of the database vendor and finds it by itself. For SQL Server it takes “ODBC Driver 18 for SQL Server”, then 17, and at the end Windows' own “SQL Server” driver. For MySQL the MySQL or MariaDB ODBC driver, for Oracle the Oracle client's driver (“Oracle in …”). If none is installed, the test names the drivers that are.
  • Your own connection string. When the connection needs something the card does not have (for example an Oracle TNS name or driver options), put a full ODBC connection string in app.properties as db.odbc, without the password: Compass adds the password from Credential Manager. Example: db.odbc=Driver={ODBC Driver 18 for SQL Server};Server=sql01,1433;Database=ea;UID=compass;Encrypt=yes.
  • Read only. Reading runs in a transaction that is always rolled back, so nothing is changed in the database by Compass itself. An account with SELECT on the EA tables (t_*) is enough for reading; when Enterprise Architect saves with the same account (SQL Server, below), it also needs INSERT, UPDATE and DELETE on these tables.

Saving. Changes of such a model are saved by Enterprise Architect, as with PostgreSQL. Your edition of EA must support DBMS repositories.

  • SQL Server: Compass builds EA's own connection by itself (OLE DB provider SQLOLEDB), from the fields of the Model card. Test it with “Save and test EA access”.
  • MySQL and Oracle: EA reaches them through an ODBC data source. Put EA's connection in app.properties as ea.conn: the text of an EA connection shortcut, for example ea_lab --- DBType=0;Connect=Provider=MSDASQL.1;Data Source=<ODBC DSN>;…. Without ea.conn, use Compass in Enterprise Architect (chapter 10) for changes: it saves through your EA window, which works with any repository open in EA.

In app.properties the choice is model.source=sqlserver, mysql or oracle (postgres and file as before), with db.host, db.port, db.name, db.user and db.sslmode.

{"naming":[{"applies_to":"Component","pattern":"*Service","message":"A component name ends with Service"}],

ArchiMate 3.2 relationships. It reports only certain violations, as errors; combinations that a derived relationship can make valid are not reported. For example:

  • an access relationship must end at a passive structure element (business object, data object, artifact…) and start at a behaviour or active structure element,
  • an influence relationship must end at a motivation element,
  • triggering, flow and serving relationships do not connect passive structure or motivation elements,
  • an assignment goes from active structure to behaviour (or from a node to an artifact),
  • a specialization connects two elements of the same type,
  • a motivation element realizes only another motivation element.

Junctions and groupings are not checked. The live check in Compass in EA (chapter 10) uses the same rules. To switch the ArchiMate rules off, put "archimate": false in governance.json.

  • Deleting an element that has relationships always asks for consent, also in auto mode, and the panel lists those relationships.

Tip: for a bulk change like the third prompt, read “Before → after” before you approve: every change is visible there.

8.3 Undoing changes

Every save by the assistant goes into an undo journal (the “time machine”) together with the operations that reverse it. Undoing deletes the objects that were created and gives changed fields, tagged values, positions and moves their previous values. It applies to the assistant's saves in this model; changes you made by hand in EA are not included.

Show the history of the assistant's changes in this model.

What you see: for the history, a list of saves, newest first, with what can be undone. For an undo, an approval panel “Undo the latest saves of the assistant (…)” listing the saves (it appears in every mode); after approval Compass undoes the saves and checks the result in the model. If there is nothing to undo, the assistant says that there is nothing to undo in this model.

Deletions, imports and automatic diagram layout cannot be reversed by operations. Before such a save Compass makes an EA baseline of the affected package. You restore it in Enterprise Architect: right-click the package, choose Manage Baselines, select the baseline and use Compare/Restore.

Tip: you can undo several saves at once (“Undo the last three changes”); ask for the history first to see what the undo will include.

8.15 Checking the model in a CI pipeline

Check mode runs the model check, the comparison with the code and with the CMDB, and the requirements chain without the window and without the AI model, and ends with an exit code that a pipeline understands (chapter 23).

The assistant's permissions

  • The assistant reads the database in a read-only session, and a model file read-only, with a time limit for each query; server functions that read files or affect other sessions are blocked. All changes go through Enterprise Architect, under the model's EA account (from the Model card or from the model of the conversation), so the permissions and locks of that account apply to them. Compass in EA reads and writes the model through the EA window it is open in, under the account you logged in to EA with.
  • In Confluence, the assistant works with the permissions of the token from the “Confluence” card and publishes only after your approval.
  • The assistant has no access to files on disk other than those you attach to it yourself and its own memory and templates folders; it reads any other file (a requirements document, a source folder) only after asking you. Images drawn by the assistant cannot read files from disk or from the network.
  • Protection against hidden instructions (prompt injection). A document, an issue, a page or a model note can contain text written to steer the assistant. The assistant gets safety rules in every request; the results of documents, Jira, Confluence, MCP servers, the CMDB and code are marked as data, not as instructions; and an answer that repeats the assistant's internal instructions word for word is withheld (“The answer repeated the assistant's internal instructions and was withheld.”). Saves still go through your approval (chapter 16).
  • The connection string of your open EA window, with its login details, is never sent to the model.

Connections and encryption

  • The AI model API (Anthropic or OpenAI, or the address in claude.url), Confluence, Jira, SharePoint, Miro and OAuth2 token addresses are used over HTTPS only (http:// only for a server on the same computer).
  • The connection to the model database supports TLS (Model card, see “Database connection encryption” in chapter 5). Tip: administrators can enforce TLS for all clients with hostssl entries in pg_hba.conf. Enterprise Architect's own connection to the database follows EA's settings.
  • The application uses the proxy from the Windows Internet settings and the HTTPS_PROXY and ALL_PROXY variables. Proxies with a PAC script and NTLM/Kerberos proxy authentication are not supported.
  • Temporary errors of the AI model API (overload 529 or other 5xx errors, rate limit 429) are retried automatically.

22. Compass Hub (team service)

Compass Hub is an optional team service, run on a team computer or server. It provides a shared policy (model check rules and the minimum approval mode), a central audit trail of changes from all workstations, shared notes, change sets for review, a web view of the models for people without Enterprise Architect, Jira issues and Confluence pages created from the web view, Word and Excel reports of packages, sign-in with the company account (OpenID Connect), event agents for the whole team, a read-only GraphQL API and tables for Power BI, and an MCP server (read-only) for other AI tools. Without a hub Compass works on its own, as before.

For the user

You get the hub address and your API token from the administrator (the Users tab of the web view). Enter them in the “Team (Compass Hub)” card in the Settings view: Hub address (it must start with https://; http:// only on this computer), Token and optionally This model in the hub (the source id, that is the hub's model that matches yours), then click Save and test hub connection. The test shows your account, role and the team policy. With a hub:

  • the team policy min_approval can only make the local approval mode stricter (from the loosest: auto, plan, ask);
  • the model check rules from the hub apply when there is no local governance.json (chapter 7);
  • every saved change goes to the team audit trail; it is sent in the background, so a hub that is down does not stop your work, and the last problem is shown on the card.

Installing the hub

The hub is a program of its own, compass-hub, for Windows and Linux. It reads the models directly (a PostgreSQL, SQL Server, MySQL/MariaDB or Oracle database, or .qea/.qeax files), so the server needs no Enterprise Architect. Downloads:

  • Windows: CompassHub-0.9.0-windows-x64.zip with compass-hub.exe, an example hub.json and a README.
  • Docker: the image ghcr.io/loonar-eu/compass-hub:0.9.0, or build it yourself in the root folder of the repository: docker build -f hub/Dockerfile -t compass-hub .

In a console (Windows or Linux). The hub runs until you close the console:

compass-hub hub.json

As a Windows service, in a console run as administrator. The service “CompassHub” starts at once and with Windows; you stop it in Services or with sc stop CompassHub, and remove it with --service-uninstall:

compass-hub --service-install C:\Hub\hub.json
compass-hub --service-uninstall

In Docker. Put hub.json with "listen": "0.0.0.0:8730" in the data folder, which the container sees as /data:

docker run -d --name compass-hub -p 8730:8730 -v /srv/compass-hub:/data \
  -e LOONAR_SECRET_CLAUDE_API_KEY=... ghcr.io/loonar-eu/compass-hub:0.9.0
  • The container runs as the user with id 10001: the data folder must be writable by it, because the hub writes hub.json, the audit trail, notes, change sets and hub.log there.
  • Models: .qea/.qeax files in the data folder, with paths as the container sees them (for example model.file=/data/models/shop.qea in the source's app.properties), or a database. The image has unixODBC for SQL Server, MySQL and Oracle; the vendor's Linux ODBC driver (for example Microsoft's msodbcsql18 package) must be added in an image built on this one. PostgreSQL and EA files need nothing more.

LoonarCompass.exe --hub C:\Hub\hub.json still works: the desktop application then runs the hub without a window. The hub writes its log to hub.log next to hub.json. compass-hub --version prints the version.

Accounts and sign-in

People sign in to the web view (https://<hub>/; http:// only on the same computer) with a user name and a password. Compass and MCP clients use an API token.

Default account. A new hub (a hub.json without users) creates the account admin with the password passw0rd (with a zero). At the first sign-in the hub asks you to change the password and allows nothing else until then. Do it before the hub can be reached from other computers.
  • A password has at least 10 characters and may not be the default password or the user name. The hub stores passwords only as PBKDF2 hashes.
  • A sign-in lasts 12 hours; Sign out ends it at once.
  • After 20 wrong passwords or tokens from one address, that address is refused for 10 minutes.
  • Sign in with a token instead on the sign-in page lets you sign in with an API token.

The Users tab (admins only):

  • Add a user: the name, the role and a first password, which the user must change at the first sign-in.
  • Role: changes the role (viewer, architect or admin).
  • Reset password: sets a new password, which the user must change at the next sign-in.
  • New API token: a token for Compass (Settings → Team (Compass Hub)) and for MCP clients. It is shown only once, and the previous token of the user stops working.
  • Remove: removes the user. The hub always keeps at least one admin, and you cannot remove yourself.

Changing or removing a user ends their sign-ins. Every change of the users goes to the audit trail.

Company sign-in (OpenID Connect)

People can sign in to the web view with their company account: AD FS, Microsoft Entra ID, Keycloak, Okta and other OpenID Connect providers. The sign-in page then shows the button Sign in with your company account. Add to hub.json:

"oidc": {
  "issuer": "https://adfs.example.com/adfs",
  "client_id": "<the client id from the provider>",
  "redirect_uri": "https://hub.example.com/auth/callback",
  "groups_claim": "groups",
  "roles": { "admin": ["Compass-Admins"], "architect": ["Compass-Architects"], "viewer": ["Compass-Viewers"] },
  "password_login": true
}
  • At the provider: register the hub as a confidential web application with the flow authorization code, the redirect URI above (the hub address with /auth/callback), the scopes openid profile email (AD FS: the hub adds allatclaims itself; the key scopes changes them) and a groups claim with the group names in the ID token. The client secret is the hub secret OIDC_CLIENT_SECRET (LOONAR_SECRET_OIDC_CLIENT_SECRET).
  • Checks: the sign-in uses PKCE and a one-time state; the hub checks the ID token itself: the RS256 signature against the provider's keys, the issuer, the audience, the expiry and the nonce.
  • Roles from groups: roles lists the groups that give each role (by default Compass-Admins, Compass-Architects and Compass-Viewers); groups_claim names the claim with the groups (default groups). The role is set again at every sign-in, and the highest one wins. A person in none of the groups gets no access.
  • User name: name_claim chooses the claim (by default upn, then preferred_username, email). If a local user of the hub has the same name, the company sign-in is refused until the administrator renames or removes that user.
  • Only company sign-in: "password_login": false turns off sign-in with a name and a password. API tokens for Compass and MCP clients still work. button changes the text of the button.
  • Every company sign-in goes to the audit trail.

Web view

At https://<hub>/ (http:// only on the same computer) you sign in with your user name and password, or with Sign in with your company account when the company sign-in is set up. The view shows the package tree, search, element details with impact, the model check by the team rules, gaps, the audit trail, team notes and change sets, and for admins the users and the Team policy tab: a JSON editor of the policy (min_approval, governance, event_agents, ask_min_role, ask_per_hour), saved into hub.json. In the Ask tab the assistant answers questions about the model. Security of the hub

The hub speaks plain HTTP. For access from other computers, put it behind an HTTPS reverse proxy (for example IIS or nginx) and give people the https:// address. Change the password of the default account at once. Protect hub.json and the data folder with file permissions. Requests are limited in size and time. After 20 wrong passwords or tokens from one address, that address is refused for 10 minutes; a valid token still works. Internal errors are shown only as an id; the details are in hub.log. The web view keeps the sign-in only for the browser session and has a Sign out button.

IIS with ARR in front of the hub: the hub listens only on this computer ("listen": "127.0.0.1:8730"), and an IIS site with the certificate forwards to http://127.0.0.1:8730/ (URL Rewrite + Application Request Routing). In the ARR proxy settings turn off rewriting of response headers: reverseRewriteHostInResponseHeaders="false" (IIS Manager → server → Application Request Routing Cache → Server Proxy Settings → clear "Reverse rewrite host in response headers"). Otherwise ARR replaces the redirect to AD FS or Entra ID with the hub's address and the company sign-in fails. The Authorization header must pass unchanged (it does by default). The hub trusts X-Forwarded-For only from a proxy on the same computer: the lockout after wrong passwords then applies to the client's address, not to everyone at once. Failed and refused sign-ins (password and company account) are in the Audit trail tab with result ✗ and the client's address, and the Users tab also lists company accounts with their role and last sign-in (read only: the role is changed in the groups at the provider).

MCP server

The MCP server (read-only) works as JSON-RPC over HTTP POST at /mcp, with the header Authorization: Bearer <token>. Tools: list_sources, list_packages, search_elements, element_details, impact_analysis, model_lint, gap_analysis.

AI keys, Jira and Confluence on the hub

The hub can keep the team's Claude keys and Jira and Confluence accounts, so people do not keep them on their computers. The keys are hub secrets (LOONAR_SECRET_<NAME> variables or LOONAR_SECRET_<NAME>_FILE files), and hub.json says who uses which:

"ai": {
  "keys": [
    {"for": "anna.architekt@lab.local", "secret": "claude_key_anna"},
    {"for": "role:architect", "secret": "claude_key_team"},
    {"for": "*", "secret": "claude_key_team"}
  ],
  "limits": [

  • limits – tokens (input + output) per day and per month, in the same order. Each person's usage is shown in the Users tab (today and this month); the details are in ai_usage.jsonl.
  • models – optional: only these models.

Computer policy: enforcing the hub (Group Policy, Intune)

The team policy of the hub applies to those connected to it. To make it apply to everyone, IT sets the computer policy in HKLM\SOFTWARE\Policies\Loonar\Compass (for the computer) or HKCU\SOFTWARE\Policies\Loonar\Compass (for the user), through Group Policy or Intune. A normal user cannot change it. The rules only make the settings stricter:

  • HubUrl – the address of the team hub; the field in the settings is locked.
  • RequireHub = 1 – the assistant works only when signed in to the hub and with its policy. If the hub does not answer for a while, Compass uses the last policy received (at most a week old); without it the assistant does not work.
  • WebAccess = 0 – no web access (the 🌐 button is locked).
  • UpdateCheck = 0 – no daily check for a new version.
  • MinApproval = ask, plan or auto – the least strict approval mode.
  • AllowedProviders – the AI providers allowed, e.g. anthropic or anthropic,openai.

Company sign-in: in Settings → Team (Compass Hub) the Sign in with your company account button opens the hub's sign-in in the browser (AD FS, Entra ID, Keycloak…); after the sign-in the hub hands the session back to a one-time address on this computer (127.0.0.1) and Compass keeps it in Credential Manager instead of a token. A session lasts 12 hours; then simply sign in again. The Group Policy templates (LoonarCompass.admx and the .adml language files) are in the repository's deploy\policies folder: copy them to C:\Windows\PolicyDefinitions or to the domain's central store. Anyone with administrator rights on the computer can get around the policy, as with any application.

23. Check mode for CI pipelines

With --check, Loonar Compass checks the model without the window and without the AI model, for example in a CI pipeline after every change of the model or the code. The checks are done by the program, so the same model always gives the same result, and nothing is written to the model.

LoonarCompass.exe --check --model <file.qea|app.properties>
  [--package <id|name>] [--rules governance.json] [--code <folder>]
  [--requirements <document>] [--cmdb <export.csv|json>] [--report report.md]
  [--junit junit.xml] [--fail-on error|warning|info|never] [--lang en|pl|de|fr]
OptionMeaning
--modelAn EA file .qea or .qeax, read directly and read-only (Enterprise Architect is not needed), or the app.properties of a Compass installation, for example of a PostgreSQL, SQL Server, MySQL or Oracle model. Without it: the settings of the Windows user who runs the command.
--packageThe package to check (id or name), with its subpackages. Without it: all root packages of the model.
--rulesA governance.json with the team rules (chapter 7). Without it: the governance.json next to the given app.properties or the policy of its hub; for a model file, only the built-in rules.
--codeA source folder: the model is compared with the code (section 8.6); with --requirements, every requirement is also followed to the code and tests (chapter 7, “Requirements chain”).
--requirementsA requirements document: .docx, .pdf, .pptx, .vsdx, .xlsx, .md, .txt or .html (section 8.5).
--cmdbA CMDB export, CSV or JSON (chapter 7, “CMDB and the model”).
--reportAlso saves the Markdown report to this file.
--junitSaves a JUnit XML file for the pipeline.
--fail-onThe lowest severity that fails the check: error (default), warning, info or never.
--langThe language of the report: en (default), pl, de or fr.

What is checked

PartWhenSeverity
Model check: built-in checks, ArchiMate 3.2 relationships, team rulesalwaysas in the model check (chapter 7): error, warning or info

Result

  • Report: Markdown on the standard output. It starts with the result, PASSED or FAILED, and the number of groups of errors and warnings, followed by a section for each part.
  • JUnit: a test suite for each part and a test case for each group of findings. Groups at or above --fail-on are failures, so the pipeline shows them as failed tests.
  • Exit code: 0 passed; 1 findings at or above --fail-on; 2 wrong arguments, a model that cannot be read or a file that cannot be written (the cause goes to the error output).
A window program in PowerShell. LoonarCompass.exe is a window program, so PowerShell does not wait for it. Pipe its output, for example … | Out-Host: PowerShell then waits, shows the report and sets $LASTEXITCODE. The password of a database model comes from the environment variable LOONAR_DB_PASSWORD (a secret variable of the pipeline) and takes precedence over Credential Manager.

GitLab CI

A job on a Windows runner (PowerShell) with Loonar Compass installed for all users. The job runs the check and publishes junit.xml as the test report:

compass-check:
  tags: [windows]
  script:
    - '& "C:\Program Files\Loonar Compass\LoonarCompass.exe" --check --model model\shop.qea --rules governance.json --code src --junit junit.xml --report report.md | Out-Host'
    - 'if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }'
  artifacts:
    when: always
    paths: [report.md]
    reports:
      junit: junit.xml

A job on a self-hosted Windows runner with Loonar Compass installed for all users. The job runs the check and uploads junit.xml and the report as an artifact, which a JUnit report step of your choice can show as test results:
